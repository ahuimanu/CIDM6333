Break the provider and watch the breaker

Your agent calls a model route over and over. Set the provider to failing and make calls. Each failing call waits out its timeout. After N failures in a row the breaker opens, and calls fail at once with a reason instead of waiting. After the cool-down, one trial call decides whether it closes again.     Two ways to ship the same release

    The deck's strip under both columns: a version number is a name. The hash is the release. Record the hash when you release and check it when you roll back.

    E12 slide 4 · Ch. 21.1

    Serving an agent: a service or a job

    Service (request/response)

    • A caller sends a request and waits; FastAPI in front of your loop
    • Every request has a time budget; the loop halts inside it
    • A retried POST must not run the agent twice: idempotency key
    • Long answers stream
    • /health reports status and version

    Job (run to completion)

    • A trigger starts a run; nobody waits on a socket
    • A turn and dollar budget, not a request timeout
    • Output is an artifact: a branch, a report, a ledger entry
    • The result must say what it did
    • Exit code is the only status the scheduler sees

    Pick one in an ADR and state the lifecycle. The deck's mistake is a service with job semantics: a POST that starts a ten-minute loop, a client that times out at 60 seconds and retries, and three agents doing the same work with your key. A request that outlives its caller becomes an orphan, so decide who owns the halt.

    E12 slides 8 and 16 · Ch. 21.3

    Who attests a job nobody watched?

    1. Stored trigger. An authorized person wrote the prompt and schedule ahead of time. The firing is evidence of storage, not of consent for this run's actions.
    2. Isolated environment. A fresh VM or runner per run; network limited by default.
    3. Narrow write path. One branch with a known prefix (copilot/, claude/, codex/). No push to a protected branch; no merge by the agent.
    4. Human merge. A person with write access reviews the diff and merges.
    5. Record and read. A green status means the run exited. Somebody reads the transcript.
    The trigger “attests only that the prompt was stored ahead of time” and “can't act as approval or consent for actions during the run.”Claude Code routines documentation, as quoted in E12 slide 16

    The run's record must answer three questions: what did it change, under whose authority, and who accepted it. For your system, a scheduled run writes only to its own branch or file, a person accepts it, and the ledger shows the run and the acceptance as two events.

    The Heavy lane and the release ceremony

    1 · ADR2 · TDD3 · Docs4 · BDD5 · Human

    Lite ran gates 1–2 all term. The Final System runs gates 1–5. Gates 3–5 are the ones a release adds.

    • Docs. The README, the runbook, and the release notes describe the release that exists. A command in the docs that fails when pasted is a gate failure.
    • BDD. Scenarios for the external contract, what a caller of /runs or a user of the CLI can rely on. Executed, not just written.
    • Human. A person attests Completed, Completed — Partial, or Dropped. The attestation is a ledger event. The agent never records it for you.
    • Release notes and changelog. The changelog is every change, for maintainers. Release notes are what a user must know to upgrade and to roll back.

    What the figure leaves out

    • The two hash prefixes and the 0.1 s rollback time come from the deck's lab run of relcheck 0.1.0 on 09/24/2026. The figure reuses them for one release. Every number in the circuit-breaker simulation is illustrative.
    • The deck states the breaker rule as “after N failures, stop calling for a period and fail the run with a reason.” The half-open trial call is the standard form of the pattern in Nygard's book; the figure draws it, and the simulation counts timeouts as failures.
    • Ledger lines use the flight card's shorthand. Your release-ledger.jsonl will hold the same facts as JSON fields.
    • The figure draws one deploy environment. A registry, a TLS proxy (FastAPI's --proxy-headers), streaming, and the idempotency store are on the deck's slides but not in the diagram.
    • gzkit items carry the deck's verify markers: the distribution invariant's exact wording, what #830 backfilled, and ADR-0.0.74's text.
