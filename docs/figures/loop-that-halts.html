The minimal loop, line by line

These twelve lines come from the deck. The highlighted lines belong to the step shown in the figure above. Each comment that says halt is one exit in the diagram.

messages = [system, user]for turn in range(BUDGET):                # halt: turn budget    step = model(messages, schema=Step)   # structured output    ledger.append("turn", step)           # ledger first    if step.kind == "answer":             # halt: final answer        return step.text    if step.kind == "tool":        obs = tools.call(step.name, step.args)   # observation        messages.append(observation(obs))    if cost.spent > COST_LIMIT:           # halt: cost budget        return halt("budget")raise Halt("turn budget exhausted")       # halt: never silent

The error halt is not in these twelve lines. Slide 7 adds it: the harness catches the tool's exception, appends it as an observation, and halts when the error count reaches its limit. The ledger records the reason.

Teardown · AutoGPT and BabyAGI, spring 2023 · E1 slide 8

The loop with a goal and no exit

The tinted boxes are model calls. Every decision in this loop came from the model, and nothing in code could end it.

ComponentReAct (2022)AutoGPT (2023)
PlanningThought per step; no plan objectExplicit task list, rewritten each cycle
MemoryThe trace, in-windowVector store of own outputs
EvaluationNone in-loopNone; self-graded from summary
RuntimeScript; halts on finishDaemon; halts on Ctrl-C or empty wallet

The deck names three absences. Nothing checked a task's result before it fed the next plan. The goal had no performance measure and no halt. The vector store returned hallucinated facts as truth. Planning was present and fluent. Both systems lacked the same three things: a budget, an evaluator, and a record.

A strong Sortie 1, per the deck, flies all three input classes, enforces both budgets in code with a reason on every halt, and gives the Chase a ledger that replays the run. An exceptional one includes a run designed to exhaust its budget, and the ledger shows that it did.

What the figure leaves out

  • The retry budget for malformed output. When the parser rejects a Step, the deck retries before it halts with reason "format". The simulator never produces a malformed Step.
  • Detection of repeated identical actions. The simulator's ledger marks repeats, but it does not halt on them.
  • Latency. The PRD names a latency budget the user will tolerate; the figure tracks turns, tokens, and cost only.
  • Prompt caching. A provider may bill the repeated prefix at a lower rate, which flattens the cost curve without removing it. Figure 01, Two Loops, draws that split.
  • The hosted and local routes. Sortie 1 runs the same loop against both and compares latency, cost, and schema compliance.
  • The check order follows the deck's code: the cost check runs after the turn has been paid for, so a run can end slightly over its cost budget.
