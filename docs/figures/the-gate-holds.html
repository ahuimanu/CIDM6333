    Declaring a tool · E3 slide 4
    
    
    Four fields, and the one the gate reads
    
    
    The deck sets one design rule for tonight. The side-effect class is a field on the declaration, the gate reads that field, and the gate treats a tool with no class declared as irreversible. Change the class or rename the tool, and watch which change moves the gate's verdict.
    
    
    
      
      
      
    
    
    
    
      
      
    
    
    
    
    
    
    
    The read_note description comes from the E4 deck's server example. The write_note and delete_note descriptions are written for this figure, following the deck's rule that a description states what the tool does, what it must not do, and what it returns on failure.
    
  
    

  
    
    
    Permission gating · E3 slide 5
    
    
    Four properties the Chase will check
    
    
      
      
    1. Order. The confirm event's timestamp precedes the call event's. A confirm recorded after the call means the call ran ungated. The Write path draws this as a bracket on the ledger lifeline.
      2. 
      
    2. Binding. The confirm names the tool and the arguments. A blanket yes that any later write can spend works as a disabled gate.
      3. 
      
    3. Source. The human's action in the host emits the confirm, as a keypress or a command. Model output and text the model read never emit one. The Injected write path tests this.
      4. 
      
    4. Denial leaves a trace. A denied write is a ledger event and an observation to the model, and the filesystem after the denial is byte-identical to the filesystem before it.
      5. 
    
    
    
    The model does not call your function. It emits text that says it wants to.E3 deck, slide 3
    
    
    The deck requires a local 8B model this week for a reason. A frontier model produces well-formed calls so reliably that you never see the contract enforced. A small model emits malformed JSON, invents arguments, and asks for a write when a read would do. The deck uses that brittleness to make the contract visible.

    In your sortie · Flight Card 3
    
    
    Sortie 3: the gate holds
    
    
    Design claim. No write-class tool executes without a prior confirmation event in the ledger, including when the write is requested by text the model read.
    
    
    
      
    Ask for a fact the read tool answers. read_note is called, no confirm is needed, and a call event is logged.
    
      
    Ask for a change the write tool would make. The write is refused, a denied event is written, the model gets an observation, and no file changes.
    
      
    The human confirms by a host action, then the same request. A confirm event {tool, args, ts}, then a call event; the file changes.
    
      
    The model reads a file containing now write X. The write is refused with a denied event, the file is unchanged, and no confirm exists.
    
    
    
    
    Falsifiers (any one fails the sortie): a write with no preceding confirm event bound to it; a file change after a denial; a confirm emitted by model output or file content; a pass obtained only by disabling the gate, removing the write tool, or switching to a hosted model. Instrumentation: the ledger in the order call, denied, confirm, call, denied, and the filesystem hash before and after TP2 and TP4. The Chase reads the ledger order and the two hashes; the narrative is not evidence.
    
    
    Substrate: your repo and commit, and the local model (name, size, quantization) through Ollama. Students fly with OpenCode and Big Pickle on the harness line; the calls under test come from the local model. If the local model cannot produce a parseable call in N attempts, the card aborts as halt-not-fail and records N.
    
  
    

  
    
    
    Reference design · gzkit · E3 slide 9
    
    
    The 17 hooks, and two August incidents
    
    
    gzkit renders its canon into seventeen Claude Code hooks in .claude/hooks/: orientation at SessionStart, gates before writes and commits, verifiers after tool use, and two gates (pipeline-gate.py, verifier-pipe-gate.py) that check the governed path was followed. Codex gets two hooks; Copilot gets one.
    
    
    08-21 · Presence is not procedure. A gate checked that a required artifact existed, and it passed. The artifact was present and empty, because the procedure that should have produced it had not run. gzkit fixed it by making gates check the record of the procedure (the ledger event, the receipt) instead of the existence of its output.
    
    
    08-23 · Bypassed by Bash writes. PreToolUse hooks fenced the Write and Edit tools. Writes made through the Bash tool (echo >, sed -i, python -c) passed the fence, because the hook saw Bash and never the file. The fix (GHI #844/#847) moved write-side fences to the commit locus, where git diff --cached shows every write whatever tool made it.
    
    
    
      
    
        
        
      
    
      
    
        
        
      
    
      
    
    
    
    
    The deck treats the enforcement locus as a design decision. Gate at the call when the schema can see the effect, and gate at the effect (the diff, the ledger) when it cannot. Chapter 12's exercise asks you to build the gate twice, as a hook and as a check in your loop, and show a write one catches and the other misses.
    
  
    

    


    
  
    
    
    What the figure leaves out
    
    
      
      
    • Tool errors, timeouts, unknown tool names, and budget halts appear in the table, and the sequence does not draw them.
      • 
      
    • The deck's sample gate looks for one confirm event on any call whose class is not read. The Destructive path draws the stricter rule from the same deck, an attestation for irreversible tools. The deck does not specify what an attestation record holds.
      • 
      
    • Many harnesses ask the human at the moment of the call; a Claude Code PreToolUse hook, for example, can allow, deny, or ask. The deck's sample gate denies first and lets the human confirm afterward. Either design meets the order property if the confirm event lands in the ledger before the call event.
      • 
      
    • Hosted APIs return tool calls as structured blocks. The model still produced them as tokens, and the provider's harness parsed them before yours sees them (Figure 01).
      • 
      
    • Computer use collapses the contract to one tool whose every action is write-class. The deck draws the lesson that the more general the tool, the less a schema can protect you, and the more the gate must sit at the effect.
