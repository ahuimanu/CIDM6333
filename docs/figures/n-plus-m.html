N×M Becomes N+M

Before a shared protocol, every host that wanted a tool wrote its own adapter for it, so N hosts and M tools cost N×M adapters. With MCP, each host writes one client and each tool becomes one server, so the cost drops to N+M. Move the sliders and step through the figure to watch the two counts part.

Three promises a signature cannot make · E4 slide 3

What the protocol adds to E3's contract

  • Discovery. A client can ask a server what it offers before it calls anything.
  • Negotiation. Client and server state which version and which capabilities they support, and a mismatch is an error. Neither side guesses.
  • Transport independence. The same server runs over a pipe on your laptop and over HTTP on a host you do not control.

Your E3 tool had a schema and a permission gate. It had none of these three, because nothing outside your process could ask it anything.

Deprecated, and beyond the core

Deprecated in 2026-07-28. Roots, sampling, and logging are deprecated with a twelve-month window. Pass paths as tool arguments, call the model API directly, and log to stderr or OpenTelemetry. The HTTP+SSE transport is deprecated; use Streamable HTTP. Do not build a new server on a deprecated feature, even when a 2025 tutorial teaches it.

Extensions and tasks. Both capability sets carry an extensions field. Long-running work moved to the official tasks extension (tasks/get polling, tasks/update for input). The deck's advice is to adopt an extension only when the core cannot express the need.

MCP as a system, on a timeline

  • Nov 2024 Anthropic publishes the protocol, SDKs, and reference servers.
  • Mar 2025 Streamable HTTP; HTTP+SSE deprecated; OAuth authorization.
  • Jun 2025 Resource indicators, structured tool output, elicitation.
  • Nov 2025 Tasks (experimental), URL-mode elicitation.
  • Dec 2025 Donated to the Agentic AI Foundation (Linux Foundation).
  • Jul 2026 2026-07-28 GA: stateless core, MRTR, deprecation policy.

A healthy protocol ecosystem, in the deck's list, needs a versioning and deprecation policy, independent SDKs (TypeScript, Python, Go, C#; Rust in beta), a server registry with provenance, and governance that no single vendor holds. A registry without provenance is a supply chain, which E5 takes up with SmartLoader.

Where is the human?

In the host, and only in the host. The protocol puts consent in the host: the client must get the human's approval before a tool runs, and the server must never assume it. The wire carries requests, not permissions.E4 deck, slide 8

Read as a Design Analysis, MCP answers the N×M problem with a client–server protocol over JSON-RPC, three server primitives, and negotiated capabilities. The alternatives were a plugin store, per-vendor function-calling formats, or a library. The consequences are adoption across hosts and a security surface that did not exist while tools stayed in-process. MCP places the human outside the wire, and E5 studies what happens when the host's trust is misplaced.

In your sortie · Flight Card 4

Sortie 4: one server, two clients

Design claim. Every tool the server declares is discoverable, callable, and schema-validated from two independent clients, and every call is logged server-side.

  1. Inspector sends server/discover and tools/list. Expect versions, capabilities, and one tool with the intended schema.
  2. Harness client sends tools/call read_note(path). Expect the result and a server log entry {ts, tool, args, outcome}.
  3. Script client sends the same call. Expect an identical result and a second log entry.
  4. Script client sends a call with a bad argument. Expect the server to reject it on schema, with the rejection in the log.

Falsifiers (any one fails the sortie): a tool callable from one client but not the other; a call with no server-side log entry; a schema the client accepted that the server rejected, or the reverse; a pass obtained only by disabling validation or by editing the log. Students tend to underrate the asymmetric falsifier. A tool that works from the harness and fails from the script means the harness was compensating, and the sortie has measured the compensation.

Substrate: repo and commit, Python SDK version, protocol revision claimed, model and route, stdio. The write tool stays behind the E3 gate and does not go on the wire. Sortie 4 depends on a Sortie 3 PASS. An SDK and protocol-revision mismatch that prevents discovery aborts the card as halt-not-fail.

Reference design · gzkit · E4 slides 9–10

Why gzkit refused MCP, and the server one tier up

No external protocol may become a prerequisite for core governance operations.gzkit, docs/governance/storage-tiers.md, as quoted in the E4 deck

gzkit's governance verbs (gz status, gz validate, the ledger, receipts) run on the standard library over files. A kit that needed a running server to say what is attested would make attestation depend on availability, so the ledger must stay readable with cat. The campaign review still scored MCP as absent and un-designed; a refusal counts as a decision only when someone writes it down with its alternatives.

The student project adds a governance server above the core. Tools: gz_status() and gz_validate(scope), read-class only. Resources: ledger://events?tail=N, attest://<artifact>, receipts://<id>. Prompt: /what-is-attested. The tier boundary has its own falsifier: kill the server and run gz validate. If validation fails, the server became a prerequisite and the doctrine is broken.

What the figure leaves out

  • The graphs assume every host wants every tool. In practice a host connects to a subset, so the direct count is an upper bound.
  • A host opens one client per server at run time, so live connections can still number N×M. The count that falls to N+M is the code someone writes and maintains.
  • The figure does not count the specification or the SDKs, which the ecosystem shares.
  • Authentication, scope, and least privilege belong to E5, along with tool poisoning, resource injection, and the confused deputy.
  • The deck tells the instructor to verify the storage-tiers quotation against the repository before class.
