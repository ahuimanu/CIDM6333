# from the deck, slide 7 (Python)
OK = {"DONE", "DONE_WITH_CONCERNS",
      "NEEDS_CONTEXT", "BLOCKED"}
def parse_handoff(text):
    try: r = json.loads(text)
    except ValueError:
        return reject("json")
    if r.get("status") not in OK:
        return reject("status")
    if r["status"].startswith("DONE") \
       and not r.get("evidence"):
        return reject("no evidence")
    return r
# There is no default branch that returns DONE.

    
This page adds two checks from the same slide's field rules (concerns required with DONE_WITH_CONCERNS, a question required with NEEDS_CONTEXT). The ReviewResult checks follow the slide's rule for verdicts.

Read-only is a permission in config

    
# .opencode/agents/reviewer.md (deck, slide 10)
---
description: Reviews one diff against one brief. Returns one ReviewResult JSON. Never edits.
mode: subagent
temperature: 0.1
permission:
  edit: deny
  webfetch: deny
  bash:
    "*": deny
    "git diff*": allow
    "git log*": allow
---

    
The deck: "The deny is the enforcement; the anti-trait 'do not edit' is the explanation." A sentence in the prompt is only a request.

  






  
Reference design · gzkit ADR-0.18.0, as the deck states it

  
The controller–worker pipeline

  

    

      
Five stages; the controller never implements

      
    
        
  1. Load context. The controller reads the brief (OBPI), its requirements, and its allowed paths. Nothing is dispatched without a brief.
    2. 
        
  2. Implement. One dispatch per task to the implementer persona; HandoffResult back; then two-stage review, spec reviewer then quality reviewer, each returning ReviewResult.
    3. 
        
  3. Verify. The controller runs the checks itself: tests, lint, the brief's verification commands. A worker's 'tests pass' is not this stage.
    4. 
        
  4. Present evidence. Paths, commands, and outputs go to the human, not conclusions.
    5. 
        
  5. Sync. Ledger events, brief status, and dispatch records written. The human attests; the pipeline does not.
    6. 
      

      
The deck's sources: docs/user/concepts/subagent-pipeline.md, src/gzkit/roles.py, pipeline_dispatch.py, .gzkit/personas/. The deck marks the ADR number, stage names, and paths "verify against the repository before class."

    

    

      
HandoffResult, dispatch records, and credit

      
HandoffResult statuses come from ADR-0.18.0: DONE, DONE_WITH_CONCERNS, NEEDS_CONTEXT, BLOCKED. ReviewResult is PASS, FAIL, or CONCERNS with findings. Both are parsed fail-closed. The field names beyond status are the course's.

      
Credit is never inferred.gzkit rule, as quoted in the E8 deck, slide 21

      
If no dispatch record exists for the spec reviewer, spec review did not happen, even if the implementer's summary says 'reviewed and approved.' A run where one agent does everything is allowed when it says so: --single-driver --reason "...". The deck marks the command that takes the flag "verify." For your sortie: if your reviewer could not run, the flight log says so and the sortie is an ABORT, not a PASS with a missing verdict.

What the figure leaves out

    
    
      
  • Parallel workers. This week's build is one implementer and one reviewer in sequence. Parallel work, with locks, is E9.
    • 
      
  • The cost. Anthropic's June 2025 post on its research system reports about 15 times the tokens of a chat turn for the multi-agent version, against about 4 times for a single agent. Cognition's counter-argument from the same month says to share full traces, because two workers with different implicit decisions build parts that do not fit.
    • 
      
  • gzkit's Stage 3 verify and Stage 4 present evidence sit between review and the human in the reference pipeline. The graph shows the LangGraph shape from slide 9, so they are listed in the reference panel instead.
    • 
      
  • The narrator, the fourth persona in the reference design, and the persona files themselves: role, traits, anti-traits, and a why sentence.
    • 
      
  • The supervisor pattern. LangChain now recommends building the supervisor with tool calling; the older langgraph-supervisor library is no longer the advised path.
