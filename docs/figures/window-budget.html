Window Budget

On every turn the model knows what is in the window and nothing else. E6 treats the window as an artifact with a budget: you know what is in it and who put it there, you log what each turn cost, and you decide what compaction may lose before it runs. Drawn to scale. The second bar converts 4,000 characters to tokens with the deck's characters ÷ 4 rule, so it is an estimate, about 1,000 tokens. OpenAI's ~100 lines has no token count in the deck and is not drawn.

    
The incident. The rendered instruction surface, AGENTS.md plus imported doctrine, grew until a Codex session's startup context was on the order of 258K tokens before the first user turn. The symptoms: compaction on turn one, rules near the end of the file ignored, and a harness that could not hold the task and the rules at once. The file had become the encyclopedia.

    
The rule that replaced it. Map, not encyclopedia (ADR-0.0.54). The file names where each kind of truth lives and what must hold on every turn. A budget is declared and validated (gz validate --instructions-files-budget). Procedures move to skills, enforcement moves to hooks, and derivable facts are deleted. The measure is what the harness loads at startup, not the file's length.

    
The deck flags this case for checking: verify the figure, the harness, and the date against the insights corpus. OpenAI's team reached the same rule from the other direction, about a hundred lines used as a map. Your E5 Sprint re-measured the 09/17 file the same way, by what the harness loaded.

  


  
  

    
Step 8, up close · load later, or load elsewhere

    
Progressive disclosure

    
Every technique trades tokens now for a lookup later. The lookup can fail, so log it. Anthropic calls the whole family just-in-time context; LangChain's four verbs (Jul 2025) are write, select, compress, isolate.

    

      
Skills
The name and description sit in context; the body loads when the skill is invoked. E5 moved procedures out of AGENTS.md into skills; E6 counts what that saved.

      
Deferred tools
Only MCP tool names enter context until a task needs one (Claude Code default).
Cursor A/B, Jan 2026: 46.9% fewer agent tokens in runs that called an MCP tool

      
Just-in-time retrieval
Keep identifiers, not contents: a path, a query, a ledger event id. Load the content at runtime with a tool. A handoff points at evidence and does not paste it.

      
Subagents
The verbose work stays in the child's window, and a summary returns.
often 1,000–2,000 tokens (Anthropic) · the summary is a claim (E9)

    

  


  
  

    
Step 9, up close · Chapter 15 · test points 3–4

    
Handoffs: writing for a stranger with no transcript

    

      
      
    

    

    

    
The test of a handoff: a stranger with no transcript takes the action you named first, and asks nothing you already answered. The machinery around it: a session-start advisement that loads the handoff before turn one (Claude Code's SessionStart hook), a rulings store so settled decisions stay settled, and an exit bookmark. The seven-section text is an illustrative skeleton.

Precedence runs L2 > L1 > L3. A compaction summary is L3: it may inform the next turn, and it may not overrule the ledger. A handoff your agent drafted is L3 until you check it against the ledger. What the figure leaves out

    
    
      
  • Prompt caching. A stable prefix is cheaper to resend, and a compaction rebuilds the cache; Figure 01 covers the bill.
    • 
      
  • Codex's server-side compaction, which returns an encrypted item the client cannot read, and Cursor's dynamic context discovery, which moves long outputs to files. Both are in the deck's teardowns.
    • 
      
  • The simulation folds the skill listing into the instruction-files segment, counts the keep list with history, and counts the re-seeded ledger tail with retrieved notes. Real summaries vary in size; this one is fixed.
    • 
      
  • Field names differ by provider. OpenAI-compatible endpoints return prompt_tokens and completion_tokens; Anthropic's API returns input_tokens and output_tokens with cache fields counted separately, so a naive sum undercounts.
    • 
      
  • Why long windows degrade: Chroma tested 18 models in July 2025 and all grew less reliable as input grew, and Liu et al. (2024) found accuracy lowest in the middle of a long input.
