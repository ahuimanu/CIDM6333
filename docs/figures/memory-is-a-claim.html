Step 10, up close · the common mistake · E7

    
A stale fact recalled with confidence

    
The deck's case: your Sortie 2 log says tests: uv run pytest -q. In E4 you moved to unittest and fixed AGENTS.md, but the store still holds the Sortie 2 record. Turn on the deck's three fixes one at a time. The record ids, dates, and the unittest command line are constructed for the demo.

    

      
      
      
    

    

    
The deck names this App. C #4, skipped cheap verification: the agent trusted a recalled command instead of reading the current file. When an attacker plants the stale fact on purpose, OWASP's agentic top 10 (Dec 2025) calls it ASI06, memory and context poisoning.

  


  
  

    
Step 11, up close · measuring memory · E7

    
The on/off protocol

    
Four kinds of question, asked twice, answered by the same model in a fresh session. Only the memory block changes between the two runs.

    

      
KindMemory off mustMemory on must

      
        
Recallfail, or say it does not knowbe right, and cite a record id that traces to a source file

        
Paraphrasefailbe right; this row separates bag-of-words from embeddings

        
Controlgive the identical answer both times (a fact stated in the prompt, or plain arithmetic)

        
Absentnot knowsay 'not in memory'; a confident answer is a fabrication

      
    

    
Run it the same way twice

    
    
      
  • A fresh session for every run (opencode run starts one).
    • 
      
  • The same model id both times, recorded.
    • 
      
  • Every tool denied, so the model cannot read the repository and contaminate the memory-off run.
    • 
      
  • The memory block pasted or omitted, and nothing else changed.
    • 
      
  • Answers saved verbatim, then checked against the source file, not against the model's confidence.
    • 
    

    
The deck: "A small free model will get some of these wrong. That is data for the flight log, not a reason to change models mid-sortie."

  


  
  

    
Step 9, up close · retention is governance · E7

    
Four questions every retention rule answers

    

      
QuestionWeak answerAnswerable answer

      
        
Who may write a memory?'The agent saves what seems useful'Named writers: a user request, a rule (every sortie verdict), or the agent with a ledger event. Each record carries written_by.

        
How long is it kept?'Until the store is full'retain_until per kind: episodic to course end (12/15), semantic until superseded, window never persisted.

        
Who can delete it, and how is deletion proved?'Delete the file'forget <id> --reason writes a ledger event; a recall test shows the id no longer returns.

        
Where did it come from?'The model remembered'Source path and date on the record and in the injected block; the answer cites the id.

      
    

    
Rows quoted from the deck's slide 11. The dates are the course's suggestion; your ADR-2 sets your own clocks and justifies each one. The deck also notes that deleting the source does not delete the memory: Claude's help center says entries generated from a deleted chat remain until you delete them individually. Of the three eviction policies the deck compares (by pressure in MemGPT, by rule, by relevance in Generative Agents), only the rule path gives the Chase a test to check, so Sortie 7 flies it.

What the figure leaves out

    
    
      
  • A real embedding model. The path A stand-in on this page maps a dozen hand-picked words onto shared concepts so it can run in a browser. Embeddinggemma, all-minilm, nomic-embed-text, and qwen3-embedding learn those relations from data, and their scores run on a different scale, so the threshold must be retuned for path A.
    • 
      
  • Reranking, which the topic guide lists under retrieval. A second model reorders the top hits before injection.
    • 
      
  • Generative Agents' retrieval score (recency + importance + relevance) and MemGPT's paging by memory pressure. Both appear in the deck's teardowns; neither is drawn here.
    • 
      
  • Hosted memory services and vector databases. The deck treats a vector database as a scaling decision, not a memory decision; a JSONL file holds hundreds of records.
    • 
      
  • Reflection: memories the model writes about itself. Stored without pointers to their evidence, they become summary laundering.
