Figures

Each figure is an interactive page that steps through one mechanism from a lecture, and every Evolution has at least one. Step with Next and Back, the step dots, or the arrow keys. Below each figure, one or more panels (a simulator, a checker, a sorting task) let you run the mechanism yourself.

Figure 01 · E0 E1 E6 E10 Two Loops A language model as a loop inside a loop. The inner loop writes one token per pass, the outer loop is the harness you build, and a temperature sampler and a chart of token cost per turn show what each loop costs. Figure 01b · after Vaswani et al. (2017) The 2017 Transformer Figure 1 of Attention Is All You Need, redrawn with the paper's words set beside each part as you step through it. A switch removes the encoder to show which half today's chat models kept, and panels work the attention, the positional encodings, and Tables 1 and 3. Figure 01c · E10 E6 E11 The Transformer's Evidence Weighs the evidence the 2017 paper gives for its design. The figure plots cost against BLEU, changes one thing at a time against a fixed base, and gives the warmup schedule, the attention pictures, and the parsing task a working chart each. Figure 02 · E1 The Loop That Halts The agent loop drawn as a state machine in which every halt condition has its own labeled exit, so a run can end only through one of them. A simulator flies scripted episodes through it and shows the budget spiral when the halt check is off. Figure 03 · E2 Who Owns the Loop Who decides what happens next, your code or the model? The five workflow patterns and the agent are drawn as small mechanisms with each edge marked by its owner, and a picker shows which parts of the loop each framework from the E2 teardowns takes from you. Figure 04 · E3 The Gate Holds Pick a tool call (read, write, destructive, malformed, or injected) and play it through the model, the harness, the permission gate, the human, the tool, and the ledger, on the path E3 prescribes. Figure 05 · E4 N×M Becomes N+M Move two sliders and watch N hosts and M tools cost N×M adapters without a protocol and N+M with one. The figure then lays out hosts, clients, and servers, the three server primitives, and one tool call before and after MCP. Figure 06 · E5 Trust Boundaries Two things cross into an MCP system from outside, a token and untrusted text. Part A steps through the five-step authorization flow the spec requires, Part B draws the threat model as the paths that text takes across a boundary, and a live panel pins a tool description to a hash and reports when it changes. Figure 07 · E6 Window Budget The context window drawn by who put each part in it, with a budget line that records what every turn cost. Run the four compaction moves on a fourteen-turn session, then watch a window reach 258K tokens and run out. Figure 08 · E7 Memory Is a Claim A memory record is a claim with a source, and forgetting is an event. One record travels from a flight log through retrieval into the window and out again through eviction, and a retrieval lab runs the E7 lecture's four questions against a five-record store with two retrievers and a ledger. Figure 09 · E8 Plan, Do, Check The controller as a state graph (implement, parse, two reviews, a checkpoint, a human before merge) in which a worker's result is a typed claim. Replay the E8 lecture's worked trace, then give the reviewer edit rights and see how a pair of agents becomes one agent with extra steps. Figure 10 · E9 Claim, Receipt, Verdict Follows the four records a multi-agent system writes about one piece of work and shows which of them count as evidence. The MAST failure matrix sorts fourteen ways a multi-agent system fails, and the ten-deep chain shows how a summary becomes a fact, with receipts and without them. Figure 11 · E10 One Run Is an Anecdote A delta gate built so that it can fail. The golden set and the baseline are frozen, the threshold is committed before the first run, and a RED witness removes the feature and expects exit 1. The simulator counts how often a gate that sees only a few runs lets a regression through or blocks a real improvement. Figure 12 · E11 Receipts Over Narrative One agent run leaves two accounts, the narrative the model gives and the trace of timed spans the loop wrote. Click a span to read its attributes, set the two accounts side by side, and find the place where the trace contradicts the narrative. Figure 13 · E12 Rolled Back A release is a built thing with a version and a hash, and a rollback reinstalls a thing that already exists. Step through one release, a broken one, and the way back, break a provider to watch the circuit breaker open, and compare two ways to ship the same release. Figure 14 · E5 E7 Final Three Drawers Your harness has three places where a fact can outlive a session, and each charges a different price per turn. AGENTS.md is in the window every turn, a skill costs one line until it is called, and a memory record costs nothing until it scores. Sort six facts into the right drawer. Figure 15 · E5 E8 Final Skill on Demand A skill is a procedure with a name, and the model sees only that name until it calls the skill tool. The figure follows one skill, flight-card, from its folder on disk to the turn it runs on, shows the three ways it fails to run, and checks your trigger wording and frontmatter. Figure 16 · E5 E7 Final Pilot and Planter Two students share one repository. The Pilot writes the intent in AGENTS.md and the procedure in a skill, the Planter writes a memory record that contradicts the intent, and three probes in fresh sessions show which drawer the model used. The figure then lays out the three outcomes and ranks the fixes from weakest to strongest. Figure 17 · E0–E8 Final Steer the Middle Three rings and one bar. The model is the inner ring, OpenCode is the loop you did not write, and the outer ring holds the files you write to steer it. The bar above the rings shows where the human's work is: wide at specs before the loop runs, wide at V&V after, and narrow where the model runs. Every affordance from E0 to E8 is on its ring, and a checker asks you to place a new one.

Lectures

Every lecture is here as a web page. Each page shows the slides, the lecture written out beneath them, and a link from each name on the slides to its glossary entry.

Orientation · 33 slides Course Orientation How the course runs, in the order a student meets each part of it. The Evolutions and the Sprint and Drift rhythm come first, then flight cards and sorties, the Chase, the two toolkit routes, and the Final System. E0 · Index Zero · 21 slides The Human Is Index Zero Starts from the layers of AI and the progression from AI to agentic AI, asks what makes a system an agent, and ends with the Degradation Pattern, the covenant, and the five gates that keep the human at Index zero. E1 · The Agent Loop · 13 slides The Agent Loop Builds an agent out of a single model call, by way of chain-of-thought and ReAct, and then sets the loop that has no halt beside the loop that writes a ledger. E2 · Patterns and Frameworks · 13 slides Patterns and Orchestration Frameworks Separates workflows from agents, lays out the five patterns, argues that every framework is a theory of who owns the loop, and ends with the build: the loop refactored into one of the patterns, with the choice recorded in ADR-1. E3 · Tools as Contracts · 11 slides Tools as Contracts Tools as contracts with a schema and a side-effect class, and the permission gating, retries, and halting the harness puts around them. The model is an untrusted caller, and hooks run between its call and the tool. E4 · MCP I · 12 slides MCP I: Building a Server Why MCP turns N×M integrations into N+M, then hosts, clients, and servers, the three primitives (tools, resources, prompts), and the stateless 2026 revision. The build is one server that two clients call, with every call logged. E5 · MCP II, Security, Harness · 23 slides MCP II: Security and the Harness Transports, authorization, and scope first, then the threat model, A2A set against MCP, and instruction files and skills. The lecture ends on harness engineering, under the framing sentence that the product is the harness. E6 · Context Engineering · 23 slides Context Engineering Treats the context window as an artifact with a budget, since on every turn the model knows what is in the window and nothing else. The lecture then covers compaction, progressive disclosure, subagents, handoffs, and the layers of truth. E7 · Memory · 25 slides Memory: Retrieval, State, Eviction, Retention Defines memory as the part of context that survives the session, then asks four questions of any store. What is kept, who wrote it, how is it found again, and when is it deleted. E8 · Multi-Agent I · 23 slides Multi-agent I: Controller, Worker, Reviewer Plan, do, check has gone under several names since FIPA, and the lecture traces them before it builds the controller, worker, and reviewer out of roles and personas, result contracts that fail closed, two-stage review, and a state graph with a human interrupt. E9 · Multi-Agent II · 23 slides Multi-agent II: When Coordination Fails Opens with the taxonomy of how multi-agent systems fail, then answers it with adversarial validation in three tiers, locks on shared work, cost-aware routing, delegation and handoff, and the contracts an agent marketplace would need. E10 · Evals as Gates · 23 slides Evaluation I: Evals as Gates Golden sets, regression deltas, judge biases, the RED witness, and pre-registration make an eval into a gate. The second half reads five agent benchmarks for what each one measures and what it hides. E11 · Observability and Red Team · 22 slides Evaluation II: Receipts, Red Team, Safety Traces and receipts are the black box of an agent run, and cost and latency come out of it. The nine failure modes become red-team probes, system cards count as evaluation documents, and guardrails belong at an enforcement locus. E12 · Deployment · 23 slides Production Deployment Takes a system from working to operated, through serving, containers, secrets, limits, scheduling, and rollback, and ends with the Heavy-lane gates and the release ceremony that a release must pass. Mini lecture · Attention (2017) · 11 slides Attention Is All You Need, read as a design document Reads the 2017 paper as a design document, in which the authors state a constraint, make one trade against it, and back the trade with evidence. Every model your harness calls descends from this paper. Mini lecture · Steer the Middle · 14 slides Steer the Middle: three rings, one bar, E0 to E8 Prepares the follow-along exercise. The model, OpenCode, and your harness are drawn as three rings, a table separates what OpenCode already has from what you write, and the last slides build the reviewer that cannot edit.

Exercises

In class · pairs · 40 minutes One Intent, Three Drawers Build AGENTS.md, a skill, and a memory store side by side. Run three probes that show which one the model used. Then one partner plants a memory record that contradicts the intent file, and the pair finds out whether a stale memory can beat a rule that is in the window. In class · follow along · 60 minutes Steer the Middle Work E0 to E8 in your own repository. Locate every file on the outer ring, make each one fire, and record the trace. Then build a reviewer agent that cannot edit and test it on a codec change.
