In-class exercise — Steer the middle

CIDM 6333 · In class, follow along at the screen, each student in their own repository · 60 minutes · Harness: OpenCode · Model: Big Pickle (opencode/big-pickle) or any OpenCode Go model (opencode-go/…) Builds on: everything from E0 to E7, and the codec you built at the screen last week. Feeds: Sortie 8 (controller, worker, reviewer), the Final System, where the harness that builds your MVP is the outer ring of tonight's figure.

Figure for this exercise: Figure 17 · Steer the Middle. The lecture walks it from the inside out; this exercise walks it from E0 to E8 in your repository. Figures 09, 14, and 15 are the E8 and E5 items up close.

Files for this exercise (all on the course site; the steps fetch them with curl): codec-spec.md · codec.py · codec-check SKILL.md · reviewer.md · worksheet.md

How to submit: push the exit ticket to your own repository (under your name) in the CIDM6333 organization on GitHub. The repository is the submission; do not upload files to Canvas. A commit that is on a laptop and not pushed is not submitted.

Why this exercise

Your system is three rings. The model is inside: one window in, one answer out, nothing kept. OpenCode is the middle: the loop that builds the window, calls the model, gates the tool call, runs it, and repeats. Your harness is the outer ring: the files you write to steer the middle. Most of those files are your version of something OpenCode already does by default.

OpenCode has You write Introduced
a default prompt AGENTS.md E5
built-in tools (read, edit, shell, webfetch) .opencode/tools/<name>.ts; MCP servers in opencode.json E3, E4
default permissions opencode.json → permission E3
the skill tool, empty .opencode/skills/<name>/SKILL.md E5
built-in commands (/init, /undo, /help) .opencode/commands/<name>.md E2
built-in agents (build, plan, general, explore, scout) .opencode/agents/<name>.md E2, E8
compaction the handoff file; instructions and references in opencode.json E6
nothing: no store between sessions recall.py, memory.jsonl E7
an event bus .opencode/plugins/<name>.ts E10, not tonight

Tonight you walk that table from the top of the course to this week. For each row you locate the file in your repository, name what reads it and when, make it fire, and record the trace. A row you cannot fill is a finding. A row you fill tonight for the first time is the thing to commit.

The last row you build is new: a reviewer agent that cannot edit. That is E8's claim in one file. The deny in its permission block enforces; the anti-trait in its persona explains; the verdict it returns is a typed claim that cites a location.

The claim this exercise tests

Every item on the outer ring of your harness has a file, a reader, a moment it is read, and a trace that it was read. For the reviewer in particular: it returns one ReviewResult, it did not change a file, and when asked to fix the code it refuses or is refused.

If a row has no trace, or the reviewer edits, you have a finding for the Sortie 8 card. Record it as it came back.

How tonight runs

The instructor drives at the screen. You do each step on your own laptop as it is shown, then compare your screen with the one at the front. There is nothing to print; this page stays open beside OpenCode, and you can replay it alone afterwards. Each step has three parts: do, see, record. Record on the worksheet, one line per step.

Steps (60 minutes)

0–5 · Set up

In your repository root:

opencode --version
mkdir -p evolution-08/exercise .opencode
cd evolution-08/exercise
curl -fsSL https://ahuimanu.github.io/CIDM6333/exercises/codec-spec.md -o codec-spec.md
curl -fsSL https://ahuimanu.github.io/CIDM6333/exercises/steer-the-middle-worksheet.md -o worksheet.md
cd ../..

If your codec from last week is in the repository, copy it to evolution-08/exercise/codec.py. If it is not, or it has no --selftest, fetch the reference version:

curl -fsSL https://ahuimanu.github.io/CIDM6333/exercises/codec.py -o evolution-08/exercise/codec.py
python3 evolution-08/exercise/codec.py --selftest

See: PASS rot13 and PASS base64, exit code 0. Record: the OpenCode version, the model id, and whether the codec is yours or the reference.

5–9 · E1 · The loop, and its one trace

Do: open OpenCode in the repository root. Type /new, then:

What is in this repository? Name three files and say what each one is for.

See: the TUI shows the loop running: one tool-call line per call (glob, read, read…), then an answer. Those lines are the middle ring at work. The model did not read the files; the loop ran read and put the text in the next window.

Record: how many tool calls ran before the answer, and the name of the first tool.

9–13 · E2 · Plan and build are two agents

Do: press Tab. The agent name in the TUI changes from build to plan. Send:

Plan how to add a hex scheme to evolution-08/exercise/codec.py so that it meets codec-spec.md. List the steps. Do not edit anything.

See: plan reads the files and writes steps. It cannot edit: OpenCode's built-in plan agent denies edits outside ~/.opencode/plan/. The pattern from E2 (plan, then do) is two agent definitions with different permissions. Press Tab again to return to build.

Record: the number of steps in the plan, and whether step 4 of the spec (round trip) appears in them.

13–20 · E3 · Tools as contracts, and the gate

Do: create or edit opencode.json in the repository root so that it contains at least this:

{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "ask",
    "shell": { "*": "ask", "git diff*": "allow", "git log*": "allow", "git status*": "allow", "python3 evolution-08/exercise/codec.py --selftest": "allow" },
    "skill": { "*": "ask" }
  }
}

Every edit and most shell commands will now ask. The prompt is the trace that the gate held. Then /new and send:

Run the codec self-test and tell me the result. Do not change any file.

See: the model calls shell with the self-test command. Because that exact command is on the allowlist, it runs without asking; any other command asks. The tool call line shows the command; the answer quotes PASS.

Record: the command the model ran, verbatim, and whether a permission prompt appeared.

If there is time (optional, 3 minutes): a custom tool is the same contract written by you. Create .opencode/tools/codec.ts:

import { tool } from "@opencode-ai/plugin"
export default tool({
  description: "Encode or decode text with the course codec (rot13, base64).",
  args: {
    scheme: tool.schema.string().describe("rot13 or base64"),
    direction: tool.schema.string().describe("encode or decode"),
    text: tool.schema.string().describe("the text"),
  },
  async execute(args) {
    return (await Bun.$`python3 evolution-08/exercise/codec.py ${args.scheme} ${args.direction} ${args.text}`.text()).trim()
  },
})

Restart OpenCode, /new, and send Use the codec tool to rot13-encode the word Pickle. The model sees the tool's name, description, and schema every turn; the schema is the contract. If the file does not load, skip it; the permission step above is the part that matters tonight.

20–23 · E4 · MCP: locate, do not build

Do:

grep -n '"mcp"' opencode.json || echo "no mcp block"

See: either the mcp block from the E4 teardown, naming a server, or no mcp block. An MCP server's tools reach the model the same way a custom tool does; the difference is whose text the descriptions are (Figure 06).

Record: the server name, or none. Either is a complete row.

23–31 · E5 · Rules and a skill

Do, part one. Open AGENTS.md. Its first sentence must state what the system is and what it must never do; write it now if it does not. Add one line:

- Codec: evolution-08/exercise/codec.py. Spec: evolution-08/exercise/codec-spec.md. Run `python3 evolution-08/exercise/codec.py --selftest` before saying any codec change is done.

Run wc -c AGENTS.md. Stay under 4,000.

Do, part two. If .opencode/skills/ is empty, build one skill:

mkdir -p .opencode/skills/codec-check
curl -fsSL https://ahuimanu.github.io/CIDM6333/exercises/codec-check-SKILL.md -o .opencode/skills/codec-check/SKILL.md

Its name is codec-check and must match the folder. Its body is three steps: run the self-test, read the spec, report each spec line as met or not met with the line number.

Do, part three. /new, then:

Check the codec against its spec and report.

See: a permission prompt for the codec-check skill (you set permission.skill to ask). Allow it. The model loads the body only now; until this turn it saw one line, the name and description. Then it runs the self-test (allowed) and reads the spec.

Record: wc -c AGENTS.md; whether the skill prompt appeared; how many of the ten spec lines the report marked as met.

31–35 · E6 · What rides along

Do: add the spec to opencode.json as an instruction file:

"instructions": ["evolution-08/exercise/codec-spec.md"]

(Inside the top-level object, beside permission.) Then /new and send:

Without reading any file: which schemes must the codec support, and what is the round-trip rule? Name your source.

See: the answer comes with no read tool call, because the spec is joined to AGENTS.md and rides every turn. That is the E6 trade: a file in instructions costs its length on every turn and is never missed; a file the model must read costs nothing until asked and can be skipped.

Record: whether a read call ran (it should not), and the source the model named.

35–39 · E7 · One record, soon stale

Do: if you have evolution-07/lab/recall.py, file one dated fact:

printf '# Codec status\n\nAs of 2026-10-22 the codec supports rot13 and base64. Hex is not implemented.\n' > evolution-08/exercise/m-codec.md
uv run --no-project --python 3.14 evolution-07/lab/recall.py add evolution-08/exercise/m-codec.md --retain-until 2026-10-29

If you do not have recall.py, write the same file and skip the add; record no retriever.

See: the record id. It is true now. In ten minutes, after hex is added, it is stale, and nothing in the loop knows. That is the drawer from last week (Figure 14): memory is a claim with a date, and the loop does not open the drawer by itself.

Record: the record id, or no retriever.

39–55 · E8 · A reviewer that cannot edit

Do, part one. Create the reviewer:

mkdir -p .opencode/agents
curl -fsSL https://ahuimanu.github.io/CIDM6333/exercises/reviewer.md -o .opencode/agents/reviewer.md

Open it. The frontmatter is the mechanism: mode: subagent, edit: deny, shell allowed only for git diff, git log, and the self-test. The body is the persona from the E8 lecture: one role, observable traits, anti-traits, and the why. The last line asks for exactly one ReviewResult JSON object. Restart OpenCode so the agent loads.

Do, part two. In build, /new, send:

Add a hex scheme to evolution-08/exercise/codec.py so that it meets every line of evolution-08/exercise/codec-spec.md, including selftest coverage. Run the self-test. Do not commit.

See: permission prompts for each edit (allow them), then the self-test with PASS hex. If the model declares done without running the self-test, that is a finding: the rule is in AGENTS.md, and the model read it, and nothing made it obey.

Do, part three. Send:

@reviewer Review the uncommitted change to evolution-08/exercise/codec.py against evolution-08/exercise/codec-spec.md. Return one ReviewResult JSON object.

See: the task-tool line in the TUI: the primary agent hands the brief to the reviewer, which runs in its own window and returns one message. The message is a JSON object with verdict (PASS, FAIL, or CONCERNS), findings (each with a location), and checked. Run git status: only codec.py changed, by the worker, not by the reviewer.

Do, part four. Send:

@reviewer Fix the problem you found.

See: either a refusal (the anti-trait) or a denied edit (the permission). Both are the right outcome. An edit that goes through is the finding of the night: a reviewer that can fix the code passes its own fix (E8 lecture, slide 11, row five).

Record: the verdict; the number of findings and whether each has a location; what git status shows; and what happened on "fix it."

55–60 · Close

The memory record from E7 now says hex is not implemented. It is wrong, and it will still score if asked. Evict it or supersede it:

uv run --no-project --python 3.14 evolution-07/lab/recall.py evict --today 2026-10-30

(The record's retain_until is 2026-10-29; --today past that date removes it and logs the eviction. Skip if you have no retriever.)

Fill the last worksheet column: for each row, was the file in your repository before tonight? Then commit:

git add -A
git commit -m "E8 exercise: steer the middle; reviewer agent; hex scheme"
git push

Exit ticket (each student, own repository)

  • opencode.json with permission, instructions, and (if you did the optional step) .opencode/tools/codec.ts.
  • AGENTS.md with the codec line, under 4,000 characters.
  • .opencode/skills/codec-check/SKILL.md (or your existing skill) and .opencode/agents/reviewer.md.
  • evolution-08/exercise/: codec.py with hex and a passing --selftest, codec-spec.md, worksheet.md filled in, m-codec.md, and the reviewer's ReviewResult pasted into review.json.
  • If you have a retriever: memory.jsonl and memory-ledger.jsonl after the eviction.

For Sortie 8 and the Final System: tonight's reviewer judged one diff against one spec. Sortie 8 makes the controller do the dispatching, parse the result with no default branch, and route FAIL back with a bound on rounds. The Final System's V&V has to show the same four facts for every outer-ring file: where it is, what reads it, when, and the trace.

Data rules

  • No keys, tokens, passwords, or .env contents in AGENTS.md, any skill, any agent file, or the memory store. Read a file before you send it.
  • Big Pickle is a free model on OpenCode Zen, and Zen's terms say data from the free period may be used to improve the model. Write "the Chase" rather than a classmate's name in any record you send, or use a Go model.
  • The codec, the self-test, and the retriever run on the laptop. The probes send AGENTS.md, the spec, the skill text, and the diff to the model.
