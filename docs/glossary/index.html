ADR

Architecture Decision Record: intent, decision, consequences, and alternatives, written before the code. The course's ADR-1 (E2) and ADR-2 (E7) are yours; gzkit's are numbered by release (ADR-0.18.0).

Who, when. Michael Nygard's 2011 template, as used in CIDM 6330.

Why it is in the course. Gate 1 is 'the ADR exists'. A decision with no record cannot be defended in Drift.

Read more. Nygard, 'Documenting Architecture Decisions' (2011)

Five gates

gzkit's five checkpoints on a piece of work: Gate 1 ADR (the decision is written), Gate 2 TDD (a test exists and was red first), Gate 3 Docs, Gate 4 BDD (behavioral acceptance), Gate 5 Human attestation. The Lite lane runs gates 1–2; the Heavy lane runs all five.

Why it is in the course. A model's self-review is at most Gate-4 evidence, never Gate 5 (rule GZK-GOV-007).

HandoffResult

The typed claim a worker returns to the controller: status from a closed set (DONE, DONE_WITH_CONCERNS, NEEDS_CONTEXT, BLOCKED), files changed, and evidence (the test command and its exit code). Anything that does not parse is rejected; there is no default branch that returns DONE.

Who, when. gzkit ADR-0.18.0; field names are the course's.

Why it is in the course. E8's rule one: a worker's result is a typed claim.

ReviewResult

The typed verdict a reviewer returns: PASS, FAIL, or CONCERNS, with findings that each cite a location (file:line, test id, diff hunk) and a list of what was checked. FAIL and CONCERNS need a finding; a verdict with no citations is rejected as malformed.

Who, when. gzkit ADR-0.18.0; field names are the course's.

Why it is in the course. E8's rule two: a verdict counts only if it cites evidence and its author could not edit.

Compaction

What the harness does when the context window fills: the model writes a summary of the history, and the summary replaces it. It is the middle ring's own answer to a finite window, and you did not write it and cannot review it before it happens.

Why it is in the course. E6's budget record and the handoff file exist because compaction loses what the model thought mattered.

Read more. Anthropic, 'Effective context engineering for AI agents' (2025)

Context window

The text the model reads on one call: system prompt, rules file, tool list, skill index, history, and whatever memory adds. It is rebuilt every turn and it has a budget; the more tokens in it, the less reliably the model attends to any one of them.

Why it is in the course. E6 treats the window as an engineered artifact with a budget (Figure 07).

Protocols and standards

A2A

Agent-to-Agent protocol: an agent publishes an Agent Card (identity, skills, endpoints, auth requirements); a client agent sends a Task that moves through states (submitted, working, input-required, completed) and returns Artifacts. For delegating work to somebody else's agent, as opposed to MCP for giving your agent tools.

Who, when. Google, April 2025; donated to the Linux Foundation in June 2025; v1.0 added signed cards.

Why it is in the course. E5 sets A2A against MCP; E9 uses its delegation model.

Read more. https://a2a-protocol.org

JSON Schema

A vocabulary for describing the shape of JSON data: types, required fields, enums. Tool argument schemas, HandoffResult, and ReviewResult are JSON Schema in spirit; Pydantic and Zod generate it from typed code.

Why it is in the course. A closed status enum in the schema is what makes a result parse fail-closed.

Read more. https://json-schema.org

Also appears as: schema · schemas · Pydantic · Zod

JSON-RPC

A lightweight remote-procedure-call format in JSON (version 2.0, 2010): a request has a method, params, and an id; a response has a result or an error. MCP's messages are JSON-RPC 2.0.

Read more. https://www.jsonrpc.org/specification

Also appears as: JSON-RPC 2.0

MCP

Model Context Protocol: a client–server protocol over JSON-RPC in which a host (the harness) connects clients to servers that expose three primitives, tools, resources, and prompts, with negotiated capabilities. One server serves every client: N×M integrations become N+M.

Who, when. Released by Anthropic in November 2024; the decks follow its 2025–26 revisions (Streamable HTTP, OAuth-based authorization, stateless core) and its donation to the Linux Foundation's Agentic AI Foundation in December 2025.

Why it is in the course. E4 builds a server; E5 covers its security and trust boundaries (Figure 05, Figure 06).

Read more. https://modelcontextprotocol.io

OAuth 2.1 and PKCE

The authorization framework MCP's remote transport uses: a client obtains a scoped token from an authorization server, with PKCE (Proof Key for Code Exchange) binding the code to the client that requested it. Scope limits what a token may do.

Who, when. OAuth 2.1 consolidates 2.0 and its best practices; PKCE is RFC 7636 (2015).

Why it is in the course. E5's five-step authorization flow (Figure 06).

BDI

Belief–Desire–Intention agents: an architecture in which an agent holds beliefs about the world, desires (goals), and intentions (committed plans), and reconsiders intentions when beliefs change. Bratman's philosophy (1987) became an agent architecture in Rao and Georgeff's work.

Who, when. Rao & Georgeff, 'BDI Agents: From Theory to Practice' (ICMAS-95).

Why it is in the course. What LLM agents carried forward (goal decomposition, halt as 'intention achieved or dropped') and what they dropped (an inspectable belief state).

Read more. Rao & Georgeff (1995)

CAMEL

Communicative Agents for 'Mind' Exploration: two role-playing models (an AI user and an AI assistant) solve a task by chatting, with inception prompts fixing their roles. No checker; the assistant ends the task by emitting a token.

Prompting a model to write intermediate reasoning steps before its answer, which improves multi-step accuracy on large models. Tree of Thoughts (2023) generalizes the single chain to a searched tree.

Contract net

Reid Smith's 1980 protocol for distributing tasks among agents: a manager announces a task, contractors bid, the manager awards it, the contractor reports a result or failure. The first plan-do-check with typed messages.

Who, when. Smith, 'The Contract Net Protocol' (IEEE Transactions on Computers, 1980).

Why it is in the course. The first row of E8's 'under every name' table.

The Foundation for Intelligent Physical Agents: a 1996 consortium that standardized multi-agent systems, including an agent communication language in which every message carries a performative (inform, request, propose, refuse). Judge biases

What a model grading another model gets wrong: position bias (Wang et al. 2023, 'Large Language Models are not Fair Evaluators'), verbosity, self-preference (Panickssery, Bowman & Feng 2024 showed models recognize their own outputs; Wataoka et al. 2024 argue the mechanism is familiarity), and injection (hidden text in an answer moves the score).

Methods and general terms

Agentic AI

The stage in the course's five-stage progression (foundation, creation, core systems, action, full automation) where a model perceives, reasons, plans, and acts on an environment through tools in a loop with a halt condition. An agent, in this book, is one whose reasoner is a language model and whose loop halts.

Why it is in the course. E0's two maps: the seven-layer stack and the five-stage progression.

Read more. Course Topic Guide, Chapters 1 and 2

Golden set

A fixed set of inputs with known-good outputs that an evaluation runs against every change; the regression delta is the difference between the baseline run and the candidate run. A gate turns red on a delta you pre-registered.

Why it is in the course. E10's build (Figure 11): one run is an anecdote.

Read more. Course Topic Guide, Chapter 19

JSON Lines: one JSON object per line, append-only friendly. The ledger, memory.jsonl, and golden.jsonl use it.

LLM

Large language model: a transformer trained on text to predict the next token, used through a chat or completion API. The inner ring of Figure 17: one window in, one answer out, nothing kept between calls.

A mutual-exclusion token that expires: a worker holding a lock on a file or task must renew it or lose it, so a crashed worker cannot block forever. Time To Live is the expiry.

SDK / API / CLI

A cryptographic hash: a fixed-length fingerprint of a file or string that changes if any byte changes. Receipts carry one; the golden set is pinned by one; Figure 06's hash-pin check guards a tool description with one.

Workflow versus agent

Anthropic's 2024 distinction: a workflow is a predefined sequence of model calls and tools; an agent decides its own steps in a loop. Five workflow patterns (prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer) and then the agent.
