What a language model adds — and what it does not

  • The stack above the model exists to supply what the model lacks
  • What it adds
  • No persistent state
  • A reasoner that generalizes from text.

    It reads an unfamiliar error, proposes a plan, writes the call, and explains itself. The capability classical agents never had.
  • Every session starts empty. Context, memory, handoffs, and ledgers (E6–E7) exist to supply it.
  • No ground truth
  • It has no environment of its own. Tools, retrieval, and evaluators (E3–E5, E10–E11) exist to supply it.
  • No accountability
  • It cannot answer for anything. Governance (E0, E5, E9, E11) supplies it and cannot be automated.

The LLM agent loop

  • The classical definition with a model in the reasoner slot — and a halt condition
  • Perceive
  • Reason
  • Act
  • Halt?
  • prompt · tool results · files · events
  • one model call; emits a thought and a decision
  • a tool call — or a final answer
  • final answer · turn budget · cost budget · error
  • no → the observation goes back in as the next percept
  • ReAct (Yao et al., 2022): the canonical form
  • The halt condition is the part 2023 forgot
  • Thought → Action → Observation, until the model emits a final answer. The atom every later week decorates.
  • AutoGPT and BabyAGI (spring 2023): goals, no grounding, no budget, no evaluator. A loop without a halt is a bill. Sortie 1 is 'a governed loop that halts.'

The nine components of a Design Analysis

  • The question to ask of every system — and the failure that appears when the component is missing
  • 1 Foundation
  • 2 Perception
  • 3 Planning & reasoning
  • What model, weights, data? Local or hosted?
  • What does it see: text, tool results, screens, files, events?
  • ReAct? CoT/ToT? Decomposition? Fixed workflow or open loop?
  • ✕ Cost and capability assumed, not measured
  • ✕ Untrusted input treated as instruction (injection)
  • ✕ Spirals; no halt; plans that never replan
  • 4 Tools & orchestration
  • 5 Memory & context
  • 6 Coordination
  • How are tools declared, called, permissioned, recovered?
  • What is in the window, compacted, persisted; who owns retention?
  • Single, controller–worker, crew, graph, protocol (MCP/A2A)?
  • ✕ Unschema'd calls; writes without confirmation
  • ✕ Context exhaustion; stale facts recalled as truth
  • ✕ Summary laundering; credit inferred, not earned
  • 7 Evaluation & feedback
  • 8 Governance & human
  • 9 Runtime & operations
  • What checks it, what it optimizes, how failure is detected?
  • Where is the human: index zero, in/on the loop, absent? What is attested?
  • Scheduled, observed, rolled back, billed — how?
  • ✕ Gaming the gate; judge self-preference
  • ✕ Governance theater; rubber-stamp attestation
  • ✕ No rollback; unmeasured cost and latency

A worked Design Analysis: chat assistant vs. agent harness

  • The E0 exercise, done on a slide — what makes the second one an agent?
  • Component · Chat assistant (2022–) · Claude Code / Codex CLI (2025)
  • Foundation · Hosted frontier model · Hosted frontier models; model tiers per task; no local option
  • Perception · The user's text; pasted content; maybe a file upload · Repo files, shell output, tool results, CLAUDE.md, hook output
  • Planning · One turn; the human is the loop · Open ReAct loop; plan mode; task decomposition; subagents
  • Tools · None (or a closed set the vendor runs) · Built-in read/edit/bash + MCP; permission prompts; hooks
  • Memory & context · The window, then gone; optional vendor memory · Window + compaction; CLAUDE.md as instruction file; no long-term memory
  • Coordination · Single · Main session + subagents; Agent tool; background tasks
  • Evaluation · The human reads the answer · Tests it runs; the human; nothing built in
  • Governance & human · Human on every turn by construction · Human in the loop per tool call; attestation is implicit
  • Runtime · A web page · Terminal; background tasks; cloud sessions
  • Why, and what it cost
  • The harness owns the loop: tools, permissions, hooks, compaction, subagents ship as features.

    The cost: governance is per-call and implicit; nothing records what was attested. gzkit fills that gap (component 8).

    The chat assistant is a workflow with the human as the loop.

Why governance: the Degradation Pattern

  • “You didn't lose control in one dramatic moment.”
  • Week 1
  • Week 2
  • Week 3
  • Week 4
  • You prompt carefully, review every line, and understand what is built.
  • You skim diffs and trust the green checkmarks.
  • You batch approvals; “looks good” becomes reflexive.
  • You approve PRs you did not read, for code you do not understand.
  • Three names for the same failure
  • Cognitive surrender

  • Mediated observation
    you see the summary, never the artifact

  • The Zero Doctrine and the covenant
  • The human is index zero — and the obligation runs both ways
  • The covenant: five clauses, two parties bound
  • The human defines intent (PRD, ADRs, acceptance criteria).
  • First in priority.
    Your intent drives every decision.

    Final in authority.
    You sign off, not the model.

    Cannot be automated away.
    Accountability is a property of a person, not a pipeline.

    How 'zero' evolved: zero overhead → zero drift → index zero.
  • The agent operates within constraints and flags violations.
  • Verification is mutual: tests, checks, evidence.
  • The human attests completion after observing artifacts.
  • Artifacts survive sessions.
  • Two sides: gates constrain agents, and humans must engage. Gates alone produce theater. “Specification without governance drifts; governance without methodology is theater; methodology without specification is arbitrary.”

Five gates, two lanes, and the command doctrine

  • Ceremony must earn its place; attestation cannot be automated
  • Gate · What it proves · Lite · Heavy
  • 1 ADR · Intent and trade-offs recorded before implementation · ● · ●
  • 2 TDD · Tests derived from the spec pass; RED witnessed first · ● · ●
  • 3 Docs · Documentation describes actual behavior · ●
  • 4 BDD · External contracts verified by acceptance scenarios · ●
  • 5 Human · A human observed the artifacts and attested · ●* · ●
  • Command doctrine: the Four P's
  • Degani & Wiener: philosophy → policies → procedures → practices. The cockpit is the model.

    • Accountability is non-transferable.
    • Authority must be instrumented, not asserted.
    • The model is a crew resource, not a crew member.
    • Evidence is artifacts, not narration.
  • Evolutions run Lite (gates 1–2). The Final System closes out Heavy (1–5). * Human attestation is universal; no self-close path. Closed vocabulary: Completed · Completed — Partial · Dropped.

Where a covenant sits among the governance frameworks

  • Policy frameworks say what must be true; a covenant says who does what on Wednesday
  • Policy and standards
  • Frontier-lab practice
  • The accountability gap
  • NIST AI RMF · EU AI Act · ISO/IEC 42001
  • Safety frameworks · system cards
  • Raji et al.; “Auditing Work”
  • Map, measure, manage, govern. Necessary, and silent on what one engineer and one agent do in one session.
  • What was tested, what was found. E11 reads one as a Design Analysis. They govern the model, not your use of it.
  • Audits without access, standards without enforcement, attestations nobody observed. A covenant is one engineer's answer.
  • Where it fits: below policy, inside the session, at the level of the artifact. It cannot make a model safe, certify an organization, or substitute for law. It makes one build answerable.

The instrument: the judgment loop

  • From CIDM 6330 — five questions that turn a description into a defense
  • Decision What did they (or you) actually decide? One sentence.
  • Design Analysis format
  • ~150 words · weekly · design-analyses/<system>.md · one row in LEDGER.md

    1. Sources read
    2. Nine components, one line each
    3. Why it was built this way, and what it cost
    4. Judgment loop (five items)

    Defended in consultation.
  • Characteristics privileged What quality did the decision buy: speed, safety, cost, portability, control?
  • Cost What was given up to get it? Every design choice has a price.
  • Failure mode What breaks first when the assumption behind the decision stops holding?
  • Preservation mechanism What keeps the intent alive after the person who made the decision has left the session?
