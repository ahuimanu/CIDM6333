A loop without a halt is a billThe one design lesson of 2023, stated up front

A loop with no stop condition keeps calling the model provider, and the provider keeps billing, until a human intervenes.

What E0 gave us

The model has no persistent state, no ground truth, and no accountability. The loop inherits all three gaps unless the builder designs them out: a budget (state), an observation (ground truth), a ledger (accountability).

The design claim Sortie 1 will try to disprove

The loop halts on every input class, within budget, every turn in the ledger.

False if a run exceeds the turn budget, halts with no ledger event, or answers without a reasoning turn.

From prompting to programs (2020–2022)How a prompt became a control structure

GPT-3 few-shot (2020)

Examples in the prompt steer the completion, so the prompt works as data.

Consequence for the build

Chain-of-thought is planning without commitment. No step checks the reasoning against the world.

ReAct adds the observation. The next reasoning step has ground truth in it.

An observation inside the loop makes a generative system an agent.

Chain-of-thought (Wei et al., 2022)

'Let's think step by step' (Kojima et al., 2022). The model emits its reasoning as text you can read.

Self-consistency (2022)

Sample several chains and vote. This is the first evaluator, and it multiplies cost by the sample count.

ReAct (Yao et al., 2022)

Interleave reasoning with actions and observations. The prompt becomes a loop body.

The minimal loop you will build this EvolutionMessages, a model call, a tool-or-answer decision, an observation, repeat, with a halt

messages = [system, user]
for turn in range(BUDGET):                # halt: turn budget
    step = model(messages, schema=Step)   # structured output
    ledger.append("turn", step)           # ledger first
    if step.kind == "answer":             # halt: final answer
        return step.text
    if step.kind == "tool":
        obs = tools.call(step.name, step.args)   # observation
        messages.append(observation(obs))
    if cost.spent > COST_LIMIT:           # halt: cost budget
        return halt("budget")
raise Halt("turn budget exhausted")       # halt: never silent

Structured output

Step is a Pydantic model: kind ∈ {answer, tool}, name, args, text. The parser rejects a malformed decision, and the rejection is an observation too.

Four halts

Final answer · turn budget · cost budget · error. Each lands in the ledger with a reason. A silent exit is the failure.

Two foundations

Same loop against a hosted API and Ollama's endpoint. Measure latency, cost, and schema compliance.

The PRD is WHAT, not HOWThe interview you will do before you write the loop

Belongs in the PRD

• Who uses it, and for what

• The question class it answers, and what it refuses

• What 'halted correctly' means per class

• Budgets: turns, cost, latency

• What the ledger must hold

• What the human attests, and when

Does not belong in the PRD

• Which model, SDK, or framework (that is ADR-1, in Evolution 2)

• The Step schema's field names

• For-loop or state graph

• Any code

A PRD that specifies a framework pre-decides the ADR without alternatives, which is post-hoc rationalization.

The Agent Loop

Evolution 1. Evolution 0 gave you maps and a posture. This Evolution gives you the loop, the smallest unit an agent is built from. Every later Evolution adds tools, memory, coordination, or evaluation to this loop, which is the reason an hour on its exact shape is a sound investment. The framing sentence for this Evolution is that a loop without a halt is a bill. The survey covers ReAct, then AutoGPT and BabyAGI, then the genesis of the reference design. The build is a governed loop that halts, with a PRD attested.

A loop without a halt is a bill

The lesson comes before the history. A loop with no stop condition keeps calling the model provider until a human intervenes, so the provider keeps billing, and nobody has settled who is responsible for what the loop did in the meantime. Evolution 0 established that the model has no state, no ground truth, and no accountability. The loop is the first structure the builder puts around the model, and the loop inherits those gaps unless the builder designs against them. A budget is the first piece of state, an observation is the first piece of ground truth, and a ledger is the first piece of accountability. Then read the design claim for this Evolution aloud, because every design claim in the course takes its shape: one sentence, and beside it the falsifiers that would disprove it (three, on this card).

From prompting to programs (2020–2022)

The prompt became a control structure in four steps over two years. With few-shot prompting, the examples in the prompt steer the completion, so the prompt works as data. With chain-of-thought, the model emits its reasoning as text, so you can read it, and latent planning appears in that text. With self-consistency, the builder samples several chains and takes a vote, which is the first evaluator and also the first time cost multiplies, by the sample count. With ReAct, the prompt interleaves reasoning with actions and observations, so the prompt is now a loop body. Chain-of-thought plans without commitment, because no step checks the reasoning against the world. ReAct adds the observation, so each reasoning step carries a piece of ground truth, and that one addition turns a generative system into an agent.

ReAct, read as a design document

Read the ReAct paper as a design document. The slide shows a trace in the paper's format: thought, action, observation, thought, action, finish. Work through the nine components with the room. The component map on the right holds the answers. Four of the components deserve attention. The tools are a fixed and small set, declared in the prompt. The memory is the trace and nothing else. Evaluation sits entirely outside the loop, on benchmarks, so no step inside the loop checks a thought. Governance consisted of the human who wrote the prompt and then left. The halt is the finish action, and nothing forces the loop to call it. ReAct lacked memory, a budget, and verification, and each of those three is a later Evolution.

The minimal loop you will build this Evolution

The build fits in a dozen lines, and the slide reads top to bottom. The loop starts with a message list. A bounded for-loop supplies the first halt. A model call returns a structured Step, so the decision is typed, and the parser rejects a malformed decision instead of the loop executing it. The loop appends every turn to the ledger before it does anything else with the turn. If the step is an answer, the loop halts. If the step is a tool, the loop calls the tool and puts the observation back into the messages. The loop then checks the cost budget. If the turns run out, the loop raises, and it never returns silently. That gives four halts, and the ledger records each one with a reason. You will run this loop twice, once against your hosted route and once against Ollama, and measure the difference. Some small models cannot produce the schema at all. That result is a finding about the model, so record it in the flight log rather than treating it as a bug in your loop.

Halt conditions, budgets, and day-one failures

Five failures appear on day one, and each one maps to a falsifier or an abort on your card. When the loop never halts because the model never emits an answer, the turn budget stops it, and a check for repeated identical actions stops it sooner. When a tool raises and the loop swallows the exception, treat the error as an observation and halt once the error count passes a limit. When a small model cannot produce the schema, retry within a retry budget, then halt with the reason format, and log the case as a squawk rather than as a failure of the design. When the model answers with no reasoning turn before it, that run trips a falsifier on the card. When an adversarial input asks the loop to ignore its budget, the loop halts anyway, because the budget lives in code and the prompt cannot reach it. The rule for the semester follows from the last case: the model can argue past a budget stated only in the prompt, so code enforces every budget and the ledger records every halt.

Teardown: AutoGPT and BabyAGI (spring 2023)

The second teardown is AutoGPT, and this one goes on the board with the room. AutoGPT's loop takes a goal in one sentence. The model writes a task list, executes one task with search or files or code, rewrites the list from its own summary of what it did, and goes around again. The only halt was a human closing the terminal or the API key running dry. Ask the room which component was absent. Governance was absent, because the goal had no performance measure, no halt, and no attestation. Memory was a vector store of the model's own outputs, so a hallucinated fact came back later as retrieved truth. Planning was present and fluent, and the fluency is the uncomfortable part, because a model that writes fluent plans with no grounding produces a spiral that reads as progress from inside. AutoGPT mattered for two reasons. It stated the ambition (give a model a goal and let it run), and it gave the field its first shared record of failure. The evaluators, budgets, and human-in-the-loop designs of 2024 and 2025 reply to that spring.

Live Design Analysis: ReAct vs. AutoGPT

The table puts the two side by side. In one year the loop gained an explicit plan, an open tool set, a vector memory, spawned subagents, and a daemon runtime, and it gained nothing in evaluation or governance. The reason sits in what the authors of each system built it to show. ReAct's authors built it to show that reasoning and acting improve each other, so it optimized for a benchmark and left everything else out. AutoGPT's authors built it to show that a goal is enough, so it optimized for ambition and left grounding out. Both lacked a budget, an evaluator, and a record. The operator started the reference design in January 2026 to fill that gap, two more years after the 2023 spring, and the delay shows how long the field took to act on the lesson. Your Design Analysis for this Evolution is one of these two systems. Write the one I did not do on the board.

Reference design: gzkit's genesis (January 2026)

The reference design began as the loop plus the thing the loop lacked. On January 12th, eleven days before the operator would show the system to students, the model said that only specification matters. The operator refused: specification, methodology, and governance, all three, or the loop drifts. The additions to the loop were a PRD that says what before how, an ADR that records the decision with its alternatives, a brief with allowed paths, and an append-only ledger in which every turn, gate, and attestation is an event. None of them changed the model call. Governance arrived as the missing component. The governed path you fly this Evolution is the same one: init, the PRD interview, the first ledger event, and an attestation after you have looked at the artifacts. Read gzkit's own PRD as the worked example. It is short, and it never says how.

The PRD is WHAT, not HOW

The PRD gets two minutes of its own, because the line between what and how decides whether ADR-1 will record real alternatives. The PRD states what: who uses the system, which question class it answers and which it refuses, what halting correctly means for each class, what budgets apply, what the ledger must hold, and what the human attests and when. The PRD does not state how: no model, no SDK, no framework, no schema field names, no code. If your PRD specifies a framework, you have pre-decided ADR-1 without recording alternatives, which is the post-hoc rationalization ADRs exist to prevent.

Evaluation lens: what a strong Sortie 1 looks like

The evaluation lens has three columns. A weak Sortie 1 shows a screenshot of one happy-path run, keeps the budget in the system prompt, and writes the falsifiers after the run. A sound Sortie 1 does what the card asks: it flies three input classes, enforces budgets in code with a reason on every halt, keeps a ledger the Chase can replay, measures both routes, and freezes the card at Go. An exceptional Sortie 1 adds a run designed to fail that did fail, in the ledger, a local-model failure logged honestly as a squawk, the answer-without-reasoning falsifier tested with a prompt that tempts it, and a flight-log paragraph on what the SDK hid, which is the exercise from chapter ten.

Flight Card 1 brief · governed loop that halts

The card for this Evolution sits at the center of the envelope, because this is the first sortie and nothing depends on it yet. Read the design claim. The card has three test points, one per input class, and each test point states the observable the Chase reads from the black box. The instrumentation is one turn event per model call and exactly one terminal event per run. You write the three falsifiers now, before you fly. The abort criteria keep the Chase from scoring an endpoint outage, or a small model that cannot emit the schema, as a failure of the design.

Observations are perception. Treat them as untrusted input.

Two lines close the lecture. Observations are perception, which means everything the loop reads back from the world is untrusted input, and that rule becomes the injection test point in E3. The framing line stands: a loop without a halt is a bill. Build one that stops, and can say why.
