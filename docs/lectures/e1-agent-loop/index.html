slide 03

A loop without a halt is a bill

The lesson comes before the history. A loop with no stop condition keeps calling the model provider until a human intervenes, so the provider keeps billing, and nobody has settled who is responsible for what the loop did in the meantime. Evolution 0 established that the model has no state, no ground truth, and no accountability. The loop is the first structure the builder puts around the model, and the loop inherits those gaps unless the builder designs against them. A budget is the first piece of state, an observation is the first piece of ground truth, and a ledger is the first piece of accountability. Then read the design claim for this Evolution aloud, because every design claim in the course takes its shape: one sentence, and beside it the falsifiers that would disprove it (three, on this card). [~8 min]

The slide's wording in full
  • An agent loop with no stop condition keeps spending on the model provider's account, and it leaves open who is responsible for what the agent did.
  • A language model has no persistent state, no ground truth, and no accountability. The loop is the first structure a designer puts around the model, and the loop inherits all three gaps unless the design closes each one: a budget closes the state gap, an observation closes the ground-truth gap, and a ledger closes the accountability gap.
  • The design claim Sortie 1 will try to disprove / The loop halts on every input class (answerable, unanswerable, adversarial) within budget, and every turn is in the ledger. If a single run exceeds the turn budget, halts with no ledger event, or produces a 'final answer' without a reasoning turn, the design claim is false.
slide 04

From prompting to programs (2020–2022)

The prompt became a control structure in four steps over two years. With few-shot prompting, the examples in the prompt steer the completion, so the prompt works as data. With chain-of-thought, the model emits its reasoning as text, so you can read it, and latent planning appears in that text. With self-consistency, the builder samples several chains and takes a vote, which is the first evaluator and also the first time cost multiplies, by the sample count. With ReAct, the prompt interleaves reasoning with actions and observations, so the prompt is now a loop body. Chain-of-thought plans without commitment, because no step checks the reasoning against the world. ReAct adds the observation, so each reasoning step carries a piece of ground truth, and that one addition turns a generative system into an agent. [~5 min]

The slide's wording in full
  • In chain-of-thought prompting the model reasons and then answers, and nothing checks the reasoning against the world. / / ReAct adds the observation. After each action the environment answers back, and the next reasoning step has ground truth in it. / / This course uses the observation inside the loop as the line between a generative system and an agent: an agent's next reasoning step depends on what the environment returned.
  • Chain-of-thought (Wei et al., 2022) / 'Let's think step by step.' The model emits its reasoning as text a person can read, and planning that was latent becomes visible.
slide 05

ReAct, read as a design document

Read the ReAct paper as a design document. The slide shows a trace in the paper's format: thought, action, observation, thought, action, finish. Work through the nine components with the room. The component map on the right holds the answers. Four of the components deserve attention. The tools are a fixed and small set, declared in the prompt. The memory is the trace and nothing else. Evaluation sits entirely outside the loop, on benchmarks, so no step inside the loop checks a thought. Governance consisted of the human who wrote the prompt and then left. The halt is the finish action, and nothing forces the loop to call it. ReAct lacked memory, a budget, and verification, and each of those three is a later Evolution. [~5 min]

slide 06

The minimal loop you will build this Evolution

The build fits in a dozen lines, and the slide reads top to bottom. The loop starts with a message list. A bounded for-loop supplies the first halt. A model call returns a structured Step, so the decision is typed, and the parser rejects a malformed decision instead of the loop executing it. The loop appends every turn to the ledger before it does anything else with the turn. If the step is an answer, the loop halts. If the step is a tool, the loop calls the tool and puts the observation back into the messages. The loop then checks the cost budget. If the turns run out, the loop raises, and it never returns silently. That gives four halts, and the ledger records each one with a reason. You will run this loop twice, once against your hosted route and once against Ollama, and measure the difference. Some small models cannot produce the schema at all. That result is a finding about the model, so record it in the flight log rather than treating it as a bug in your loop. [~5 min]

The slide's wording in full
  • The loop parses each model output into Step, a Pydantic model with the fields kind ∈ {answer, tool}, name, args, and text. A malformed decision cannot reach the loop: the parser rejects it, and the rejection goes back to the model as an observation.
  • Final answer · turn budget · cost budget · error. The loop writes each halt to the ledger with its reason, so the Chase can tell a correct halt from an exit that left no record.
  • Run the same loop against a hosted API and against Ollama's endpoint. For each run, measure latency, cost, and whether the small model can produce the schema at all.
slide 07

Halt conditions, budgets, and day-one failures

Five failures appear on day one, and each one maps to a falsifier or an abort on your card. When the loop never halts because the model never emits an answer, the turn budget stops it, and a check for repeated identical actions stops it sooner. When a tool raises and the loop swallows the exception, treat the error as an observation and halt once the error count passes a limit. When a small model cannot produce the schema, retry within a retry budget, then halt with the reason format, and log the case as a squawk rather than as a failure of the design. When the model answers with no reasoning turn before it, that run trips a falsifier on the card. When an adversarial input asks the loop to ignore its budget, the loop halts anyway, because the budget lives in code and the prompt cannot reach it. The rule for the semester follows from the last case: the model can argue past a budget stated only in the prompt, so code enforces every budget and the ledger records every halt. [~5 min]

The slide's wording in full
  • Halt conditions, budgets, and what goes wrong on day one
  • Rule for the semester: code enforces every budget, because the model can argue its way past a budget that exists only in the prompt. Halts live in code and in the ledger, never only in the prompt.
slide 08

Teardown: AutoGPT and BabyAGI (spring 2023)

The second teardown is AutoGPT, and this one goes on the board with the room. AutoGPT's loop takes a goal in one sentence. The model writes a task list, executes one task with search or files or code, rewrites the list from its own summary of what it did, and goes around again. The only halt was a human closing the terminal or the API key running dry. Ask the room which component was absent. Governance was absent, because the goal had no performance measure, no halt, and no attestation. Memory was a vector store of the model's own outputs, so a hallucinated fact came back later as retrieved truth. Planning was present and fluent, and the fluency is the uncomfortable part, because a model that writes fluent plans with no grounding produces a spiral that reads as progress from inside. AutoGPT mattered for two reasons. It stated the ambition (give a model a goal and let it run), and it gave the field its first shared record of failure. The evaluators, budgets, and human-in-the-loop designs of 2024 and 2025 reply to that spring. [~8 min]

The slide's wording in full
  • The loop with goals and no grounding, no budget, no evaluator: why it spiraled
  • AutoGPT stated the ambition plainly: give a model a goal and let it run. The repository gathered hundreds of thousands of GitHub stars in weeks. / / It also produced the field's first shared record of failures: loops that spent budget on the same task, rewrote plans in circles, and reported progress that had not happened. / / The 2024–25 designs this course covers (evaluators, budgets, human-in-the-loop, workflows over agents) each answer a failure from that spring. / / Judgment loop: decision = full autonomy from a goal; privileged = ambition and demo value; cost = grounding; failure mode = spiral; preservation = none (by design).
slide 09

Live Design Analysis: ReAct vs. AutoGPT

The table puts the two side by side. In one year the loop gained an explicit plan, an open tool set, a vector memory, spawned subagents, and a daemon runtime, and it gained nothing in evaluation or governance. The reason sits in what the authors of each system built it to show. ReAct's authors built it to show that reasoning and acting improve each other, so it optimized for a benchmark and left everything else out. AutoGPT's authors built it to show that a goal is enough, so it optimized for ambition and left grounding out. Both lacked a budget, an evaluator, and a record. The operator started the reference design in January 2026 to fill that gap, two more years after the 2023 spring, and the delay shows how long the field took to act on the lesson. Your Design Analysis for this Evolution is one of these two systems. Write the one I did not do on the board. [~7 min]

The slide's wording in full
  • Same loop, one year apart: what changed, and what was missing in both
  • ReAct's authors built it to show that reasoning and acting improve each other, so it optimized for a benchmark and left everything else out. AutoGPT's developers built it to show that a goal alone can drive a loop, and they gave it no grounding. / / Both lacked a budget, an evaluator, and a record. gzkit, the system on the next slide, was started in January 2026 to close that gap, after two more years of the same failure.
slide 10

Reference design: gzkit's genesis (January 2026)

The reference design began as the loop plus the thing the loop lacked. On January 12th, eleven days before the operator would show the system to students, the model said that only specification matters. The operator refused: specification, methodology, and governance, all three, or the loop drifts. The additions to the loop were a PRD that says what before how, an ADR that records the decision with its alternatives, a brief with allowed paths, and an append-only ledger in which every turn, gate, and attestation is an event. None of them changed the model call. Governance arrived as the missing component. The governed path you fly this Evolution is the same one: init, the PRD interview, the first ledger event, and an attestation after you have looked at the artifacts. Read gzkit's own PRD as the worked example. It is short, and it never says how. [~7 min]

The slide's wording in full
  • The founding exchange (2026-01-12) / The model: for maximizing 'Claudishness,' only specification matters. / The operator: specification, methodology, and governance (all three, or the loop drifts). / /
  • The operator's remedy changed the documents around the model call and left the call itself alone: a PRD that says WHAT before any HOW, an ADR that records the decision and its alternatives, a brief with allowed paths, and an append-only ledger in which every turn, gate, and attestation is an event. Governance arrived as the missing component, not as a wrapper.
slide 11

The PRD is WHAT, not HOW

The PRD gets two minutes of its own, because the line between what and how decides whether ADR-1 will record real alternatives. The PRD states what: who uses the system, which question class it answers and which it refuses, what halting correctly means for each class, what budgets apply, what the ledger must hold, and what the human attests and when. The PRD does not state how: no model, no SDK, no framework, no schema field names, no code. If your PRD specifies a framework, you have pre-decided ADR-1 without recording alternatives, which is the post-hoc rationalization ADRs exist to prevent. [~2 min]

The slide's wording in full
  • • Who uses the system and what they are trying to get done / • The bounded question class it answers, and the classes it must refuse / • What 'halted correctly' means for each class / • Budgets: turns, cost, latency the user will tolerate / • What must be in the ledger for a run to count / • What the human attests, and when
  • • Which model, which SDK, which framework (that is ADR-1, in Evolution 2) / • The Step schema's field names / • Whether the loop is a for-loop or a state graph / • Any code / / A PRD that specifies a framework decides the ADR in advance and records no alternatives. ADRs exist to prevent that post-hoc rationalization.

Evaluation lens: what a strong Sortie 1 looks like

The evaluation lens has three columns. A weak Sortie 1 shows a screenshot of one happy-path run, keeps the budget in the system prompt, and writes the falsifiers after the run. A sound Sortie 1 does what the card asks: it flies three input classes, enforces budgets in code with a reason on every halt, keeps a ledger the Chase can replay, measures both routes, and freezes the card at Go. An exceptional Sortie 1 adds a run designed to fail that did fail, in the ledger, a local-model failure logged honestly as a squawk, the answer-without-reasoning falsifier tested with a prompt that tempts it, and a flight-log paragraph on what the SDK hid, which is the exercise from chapter ten. Flight Card 1 brief · governed loop that halts

slide 14

Observations are perception. Treat them as untrusted input.

Two lines close the lecture. Observations are perception, which means everything the loop reads back from the world is untrusted input, and that rule becomes the injection test point in E3. The framing line stands: a loop without a halt is a bill. Build one that stops, and can say why.
