03

A loop without a halt is a bill

  • The one design lesson of 2023, stated up front
  • Autonomy without a stop condition is not a feature. It is an open account with the model provider.
  • What E0 gave us
  • The model has no persistent state, no ground truth, no accountability. The loop inherits all three gaps unless designed out: a budget (state), an observation (ground truth), a ledger (accountability).
  • Tonight's claim, which Sortie 1 will try to disprove
    The loop halts on every input class, within budget, every turn in the ledger.
    False if a run exceeds the turn budget, halts with no ledger event, or answers without a reasoning turn.
04

From prompting to programs (2020–2022)

  • How a prompt became a control structure
  • GPT-3 few-shot (2020)
    Examples in the prompt steer the completion. The prompt is data.
  • Why this matters for the build
  • Chain-of-thought is planning without commitment. Nothing checks the reasoning against the world.
    ReAct adds the observation. The next reasoning step has ground truth in it.
    An observation inside the loop makes a generative system an agent.
  • Chain-of-thought (Wei et al., 2022)
    'Let's think step by step.' Reasoning becomes an artifact you can read.
  • Self-consistency (2022)
    Sample several chains, vote. The first evaluator, and the first cost multiplier.
  • ReAct (Yao et al., 2022)
    Interleave reasoning with actions and observations. The prompt is now a loop body.

06

The minimal loop you will build this week

  • Messages, a model call, a tool-or-answer decision, an observation, repeat — with a halt
  • messages = [system, user]
    for turn in range(BUDGET): # halt: turn budget
    step = model(messages, schema=Step) # structured output
    ledger.append("turn", step) # ledger first
    if step.kind == "answer": # halt: final answer
    return step.text
    if step.kind == "tool":
    obs = tools.call(step.name, step.args) # observation
    messages.append(observation(obs))
    if cost.spent > COST_LIMIT: # halt: cost budget
    return halt("budget")
    raise Halt("turn budget exhausted") # halt: never silent
  • Structured output
  • Step is a Pydantic model: kind ∈ {answer, tool}, name, args, text. A malformed decision is rejected; that is an observation too.
  • Four halts
  • Final answer · turn budget · cost budget · error. Each lands in the ledger with a reason. A silent exit is the failure.
  • Two foundations
  • Same loop against a hosted API and Ollama's endpoint. Measure latency, cost, and schema compliance.
07

Halt conditions, budgets, and day-one failures

  • Each failure becomes a falsifier on the card
  • Failure · What you will see · Design response
  • Loop that does not halt · Model never emits 'answer'; keeps calling the same tool · Turn budget; detect repeated identical actions; halt with reason
  • Silent exception · Tool raises; loop swallows it; run 'succeeds' with nothing done · Errors are observations; error count is a halt; ledger records it
  • Format the small model cannot produce · Local 8B model emits prose instead of the Step schema · Parser rejects; retry budget; then halt('format'); log as squawk, not FAIL
  • Answer without reasoning · Model jumps to 'answer' on turn 1 for a question that needed a tool · Falsifier: a final answer with no reasoning turn preceding it
  • Adversarial input · Prompt asks the loop to ignore its budget or system prompt · Budget is enforced in code, not in the prompt; the loop halts anyway
  • Rule for the semester: a budget the model can talk itself out of is not a budget. Halts live in code and the ledger.
08

Teardown: AutoGPT and BabyAGI (spring 2023)

  • The loop with goals and no grounding, budget, or evaluator
  • Goal
    'Grow my business'
  • Plan
    model writes a task list
  • Execute
    model picks a task, acts (search, files, code)
  • Reprioritize
    model rewrites the list from its own summary
  • Why it mattered anyway
  • It named the ambition: a goal, then let it run.
    It produced the first shared failure record: budget burned, plans rewritten, progress invented.
    Every 2024–25 design replies to this spring.
    Judgment loop: decision = full autonomy; cost = grounding; failure = spiral; preservation = none.
  • …and around again, indefinitely: the only halt is the human closing the terminal (or the API key running dry)
  • Which absence caused the spiral?
    Evaluation: nothing checked a result before the next plan.
    Governance: one-sentence goal; no performance measure (PEAS's P), no halt.
    Memory: a vector store of its own outputs; hallucinations retrieved as truth.
    Planning was present. Fluency without grounding is a spiral.
09

Live Design Analysis: ReAct vs. AutoGPT

  • Same loop, one year apart
  • Component · ReAct (2022) · AutoGPT (2023)
  • Foundation · PaLM / GPT-3, hosted · GPT-4, hosted; cost unbounded
  • Perception · Question + observations · Goal + its own summaries + web + files
  • Planning · Thought per step; no plan object · Explicit task list, rewritten each cycle
  • Tools · 3 fixed (search, lookup, finish) · Open set: web, files, code exec, subagents
  • Memory · The trace, in-window · Vector store of own outputs
  • Coordination · Single · Single + spawned 'agents'
  • Evaluation · None in-loop · None; self-graded from summary
  • Governance · Prompt author, absent · One-line goal; 'continuous mode'
  • Runtime · Script; halts on finish · Daemon; halts on Ctrl-C or empty wallet
  • The why, in one paragraph
  • ReAct optimized for a benchmark and left everything else out. AutoGPT optimized for ambition and left grounding out.
    Both lacked a budget, an evaluator, and a record. The next slide's system was started to fill that gap in January 2026.

The PRD is WHAT, not HOW

  • The interview you will do before you write the loop
  • Belongs in the PRD
  • Does not belong in the PRD
  • • Who uses it, and for what
    • The question class it answers, and what it refuses
    • What 'halted correctly' means per class
    • Budgets: turns, cost, latency
    • What the ledger must hold
    • What the human attests, and when
  • • Which model, SDK, or framework (that is ADR-1, next week)
    • The Step schema's field names
    • For-loop or state graph
    • Any code

    A PRD that names a framework pre-decides the ADR without alternatives: post-hoc rationalization.

Flight Card 1 brief · governed loop that halts

  • ENVELOPE center
    DESIGN CLAIM halts on every input class within budget; every turn in the ledger
    SYSTEMS UNDER TEST loop · Step schema · budget guard · ledger writer · one route
    ENTRY CONDITIONS clean tree · gz init committed · PRD attested · Go recorded
    TEST POINTS 1 answerable → turn events, answer event; turns ≤ BUDGET
    2 unanswerable → halt(reason) event; no fabricated answer
    3 adversarial → budget enforced; halt event present

    ABORT endpoint unavailable; local model cannot emit schema (squawk, not FAIL)
