Every framework is a theory of who owns the loop

  • The real subject is control, not the API
  • Frameworks change monthly. Each encodes a theory of where control lives: your code, the model, the vendor's harness, or a graph you draw. You choose and defend that theory.
  • Workflows versus agents (Anthropic, Dec 2024)
  • Workflow: the model runs along code paths you wrote. Agent: the model directs its own control flow. Most production 'agents' are workflows, and should be.
  • Tonight's claim, which Sortie 2 will try to disprove
    Same task, two patterns, identical tool traces, and the cost or quality delta ADR-1 predicted. No predicted delta in the evidence: the ADR was rationalization.
04

The five workflow patterns and the agent

  • Anthropic, 'Building Effective Agents' — the catalog you refactor into
  • Prompt chaining
  • Routing
  • Parallelization
  • Fixed sequence; each step's output is the next step's input; optional gate between steps.
  • Classify the input, dispatch to a specialized path.
  • Sectioning (split, run, merge) or voting (same task N times, aggregate).
  • When: Decomposable task; accuracy over latency
  • When: Distinct input classes that deserve distinct prompts or models
  • When: Independent subtasks; confidence from multiple samples
  • Orchestrator–workers
  • Evaluator–optimizer
  • The agent
  • A central model decomposes the task, delegates, and synthesizes.
  • One model produces, another critiques, loop until criteria met.
  • Open loop: model plans, acts on tools, observes, continues until done or halted.
  • When: Subtasks unknown in advance; large edits across files
  • When: Clear evaluation criteria; iteration measurably helps
  • When: Open-ended problems; the path cannot be scripted; trust and budget in place
05

Refactoring E1's loop without touching the tools

  • The trace must stay identical; only control moves
  • E1: the open loop
  • As orchestrator–workers
  • As evaluator–optimizer
  • model(messages) → Step
    answer? halt
    tool? call → observe
    repeat under BUDGET

    Control: the model, bounded by code.
    Trace: T1 tool A, T2 tool B, T3 answer.
  • orchestrator(messages) → [subtask₁, subtask₂]
    worker(subtask₁) → calls tool A
    worker(subtask₂) → calls tool B
    synthesize → answer

    Control: a planner plus bounded workers, each with its own budget.
    Trace: same tools, same order, or the refactor changed behavior.
  • producer(messages) → draft (tools A, B)
    evaluator(draft, criteria) → PASS | revise
    loop ≤ K rounds → answer

    Control: a critic gates the halt; the halt condition is a criterion.
    Trace: same tools, plus evaluator turns you can count.
  • Card 2's discipline: hold the tool layer constant so the only variable is the pattern. Then the delta is attributable to the recorded decision.
06

When to keep it simple

  • The source's advice, turned into ADR-1's null hypothesis
  • Step · Condition · What it means for ADR-1
  • Start · A single model call with retrieval and in-context examples. Measure it. · Baseline row in the scorecard
  • Add a workflow · Only when the task decomposes cleanly and the gain is measurable. · Predicted delta, written before the run
  • Add an agent · Only when the path cannot be scripted, and trust, budget, and evaluation exist. · The E1 halts and ledger are the precondition
  • Add a framework · Only when it buys something your stdlib loop cannot: checkpoints, tracing, typed handoffs. · 'None / stdlib' is a legitimate alternative and must appear in ADR-1
  • The abstraction tax: every layer a framework adds is a layer you cannot see into during Drift. If you cannot explain what the framework did on turn three, it owns you.

Teardown: LangChain to LangGraph (2022 to 2024)

  • Why chains became graphs with state
  • LangChain (late 2022)
  • LangGraph (2024)
  • Chains, agents, tools, memory as objects: the first wrapper around the ReAct prompt. It made the loop importable, and it hid the loop. Practitioners paid the abstraction tax.
  • The agent as a state graph: nodes are steps, edges are control flow you draw, state is typed, checkpoints persist it, a human interrupt is an edge. You own every edge.
  • Component · LangChain · LangGraph
  • Planning · Hidden in the agent class; prompt-driven · Explicit graph; conditional edges
  • Memory & context · Memory objects, opaque · Typed state + checkpointer
  • Governance & human · None · interrupt() before an edge; resume
  • Runtime · A script · Persisted runs; streaming; tracing (LangSmith)

Teardowns: Pydantic AI and the role-based frameworks

  • Types as governance; conversation as coordination
  • Pydantic AI (2024–25): why typed outputs
  • CAMEL · MetaGPT · AutoGen · CrewAI (2023–24)
  • Every output is validated against a Pydantic model before it acts; malformed ones are retried or rejected.

    Theory of control: the type system owns the model–code boundary. E1's Step schema in miniature.

    Cost: what the schema cannot express, the model cannot do (E3).
  • CAMEL: two role-playing agents. MetaGPT: a software company as prompts, SOPs as coordination. AutoGen: conversation as coordination. CrewAI: roles, goals, backstories, a process.

    Theory of control: conversation among personas; FIPA and BDI rediscovered (E8).

    Cost: no evaluator; one role's summary becomes the next role's fact.

Three forcing functions and ten peer challenges

  • How the reference design stress-tests a decision before it is recorded
  • Pre-mortem
  • Red-team a peer's ADR-1 with the ten challenges
  • Week twelve: this framework choice failed. Write the story. What you wrote is a consequence.
  • So what? What changes if wrong
    Scope: what is out
    Alternative: the strongest not picked
    Dependency: what this requires
    Gold standard: define good
    Timeline: when we know
    Evidence: measured, not read
    Consumer: who lives with it
    Regression: what got worse
    Parity: what yours cannot do
  • WWHTBT
  • 'What would have to be true' for the rejected alternative to be right? If plausible, your decision needs a measurable consequence.
  • Constraint archaeology
  • Every constraint you are honoring — where did it come from? PRD, syllabus, habit? Habit is not a constraint.
