slide 03

Memory is the part of context that survives

Framing. The window from the previous Evolution is gone at the end of the session; memory is the part you chose to keep. Two rules for the whole evening. First, a memory is a claim with a source: the record says where it came from, when, and who wrote it, and a record without those fields is a rumor your agent will repeat with confidence. Second, retrieved text is data and never instruction, which is the E5 rule turned on your own store: a memory is content, and some session or some attacker wrote it. The claim is the one in chapter 16. It has two halves, recall and forgetting, and three falsifiers: a fact that was never stored, an item kept past its rule, and retrieval that changes an answer it had no business changing.

The slide's wording in full
  • Whatever survives the session can be wrong the next Evolution, and nobody will notice unless the record says where it came from
  • Memory is the part of context that survives the session. Everything that survives can be stale, planted, or never true, and it will be read as fact on every turn after.
  • A memory is a claim with a source. Every stored item carries where it came from, when, and who wrote it. A record without provenance is a rumor the agent repeats. / Retrieved text is data, never instruction. E5's rule applies to your own store. A memory that says 'always do X' is content that some session, or some attacker, wrote.
  • With memory on, the system answers a question about a prior session correctly that it cannot answer with memory off, and eviction removes exactly what the retention rule says it removes. A recalled fact that was never stored, an item retained past its rule, or retrieval that changes an answer that should not change falsifies it.
slide 04

Five kinds of memory, and where each lives

Five kinds, from chapter 16, and a sixth card that is the question for your ADR. The window is short-term memory and the harness owns it. Working state is typed: if your loop keeps its current goal in a paragraph of prose, it has no state, it has a story. Episodic memory is what happened, append-only and dated. Semantic memory is what is known, and because facts change, every update must say what it replaces. Procedural memory is skills and recipes, and it changes by review. For most of your systems the answer is episodic plus a small semantic store. Write that down first; the store follows from it.

The slide's wording in full
  • Name the kind before you pick the store; each kind has a different writer and a different clock
  • What the model sees this turn: instructions, history, tool results, retrieved text. Writer: the harness. Clock: the session. E6 budgeted it.
  • Typed fields the loop reads and writes: goal, current step, open approvals, budget left. A Pydantic object or a row, not prose. Clock: the task.
  • What happened: turns, tool calls, sortie outcomes, corrections. Append-only and dated. Reflexion's buffer and Generative Agents' stream are episodic.
  • What is known: facts about the user, the project, the domain. Mutable, so each change must name what it supersedes. RAG's Wikipedia index is semantic.
  • How to do things: skills, prompts, tool recipes. Voyager's skill library, Claude Code skills, your AGENTS.md. Changes by review, not by the agent alone.
  • Most course systems need episodic memory (sortie outcomes, decisions) and a small semantic store (user and project facts). ADR-2 says which, before you build a store.
slide 05

A memory is a claim with a source

The record is where the first rule becomes code. On the left, four operations, and each one leaves a ledger event: write, store, read, evict or forget. On the right, the record the lab uses: an id that is never reused, the kind, the source file, the date, who wrote it, a retain-until date, a supersedes field, and the text. The store and the ledger answer different questions: the store is what is remembered now, and the ledger is what was remembered on any date, which is what an auditor asks. The strip is the Chase's test: a recalled sentence with no record and no source is a fabrication even when it is right.

The slide's wording in full
  • A memory record is a claim with a source
  • Write. Who decides to store: the user ('remember this'), the agent (auto memory), or a rule (every sortie verdict). Every write is a ledger event. / Store. One record per chunk, with provenance. Append-only where you can; ids never reused. / Read. Retrieval returns ids and scores; the block injected into the prompt cites the ids. / Evict and forget. Eviction follows a rule; forgetting follows a request. Both leave a ledger event, never a silent gap.
  • If the Chase cannot trace a recalled sentence to a record, and the record to a source file, the recall is a fabrication (App. C #3), whether or not it happens to be true.
slide 06

Retrieval: chunk, represent, store, score, inject

Five steps, and each is an ADR-2 decision. Chunking first, with a finding from building this Evolution's lab tool: when the chunks lost their headings, the question about the Sortie 5 verdict returned the Sortie 3 verdict, because both chunks said 'Chase verdict' and neither said which sortie. Keeping the heading with the chunk fixed it. Represent: counts or vectors, and the same model on both sides. Store: a JSONL file is enough at course scale. Score: cosine, a small k, and a threshold, so that 'nothing found' can happen. Inject: a marked block the model must cite. The strip is when retrieval makes answers worse, and the only way to see it is to run with memory off as a control.

The slide's wording in full
  • Split by paragraph or section. Keep the heading with each chunk. Without it, 'Chase verdict: FAIL' does not say which sortie, and the lab's first test returned the wrong one.
  • Bag-of-words (term counts weighted by rarity) or an embedding vector from a local model. Index and query with the same model.
  • memory.jsonl, with vectors cached beside the text in the sortie. A JSONL file holds hundreds of records; a vector database is a scaling decision, not a memory decision.
  • A marked block: id, source, date, text. The model is told to cite the id it used. The block is data.
  • Retrieval hurts when an irrelevant hit crowds the window, a stale hit outranks the fresh one, or a planted record reads as instruction. Memory off is the control that shows which.
slide 07

Two retrievers you can run tonight

Two retrievers, both in the lab's single file. Path B is bag-of-words: tokenize, drop stopwords, weight rare terms up, compare with cosine. It needs nothing but the standard library, and it is very good at exact identifiers, which is most of what a flight log contains. It fails on synonyms. Path A calls Ollama's embed endpoint with embeddinggemma; the vectors come back unit length, so the dot product is the cosine. It handles paraphrase and costs a download, and its numbers are not auditable, so the audit is always on the text and the id.

slide 10

State and eviction

State first: working state is a typed object the loop owns, and the model proposes changes the loop validates, the same contract as your tools in E3. Then three eviction policies. MemGPT evicts by pressure: warn at about seventy percent, flush half into a recursive summary at a hundred. Retention evicts by rule: a date on every record and a command that removes past-date records and logs each one. Generative Agents evicts by relevance, which means it never deletes anything, it just stops finding it. Only the rule path gives you a test the Chase can check, so that is the one Sortie 7 flies.

The slide's wording in full
  • A typed object the loop owns: goal, step, open approvals, budget left, last verdict. The model proposes a change; the loop validates it and writes it. A prose summary is not state.
  • At about 70% of the window, a memory-pressure warning lets the model save what matters. At 100%, about half the messages are evicted into a recursive summary. The summary loses detail by design.
  • retain_until on every record; evict removes past-date records and logs each id. Deterministic and testable, which is what an auditor wants.
  • Nothing is deleted. Old, unimportant memories score low and stop surfacing. Cheap to build; you cannot prove anything is gone.
  • Sortie 7 flies the rule path: the Chase checks that each evicted id has a ledger event and is absent from the store, and that a question about it now fails.
slide 11

Retention is governance

Retention is where memory stops being a feature and becomes governance. Four questions. Who may write, and the answerable version names the writers and records which one wrote each item. How long, and the answer is a clock per kind, not 'until full'. Who can delete and how is it proved: a forget command with a reason, a ledger event, and a recall test that now fails. Where it came from: source and date on the record and in the prompt. The strip is a vendor making the same point: in Claude's help pages, deleting a conversation does not delete the memories generated from it. Deletion of a derived store is its own operation, and your system needs one.

The slide's wording in full
  • Named writers: a user request, a rule (every sortie verdict), or the agent with a ledger event. Each record carries written_by.
  • forget <id> --reason writes a ledger event; a recall test shows the id no longer returns.
  • Source path and date on the record and in the injected block; the answer cites the id.
  • Deleting the source does not delete the memory. Claude's help center says this of its own memory: entries generated from a deleted chat remain until you delete them individually.
slide 12

Measuring memory: the on/off protocol

How you measure the claim. Four kinds of question. Recall is the one the claim names. Paraphrase tests the retriever choice. Control is the falsifier 'retrieval changes an answer that should not change'. Absent is the fabrication check. On the right, the discipline: fresh session, same model, tools denied so the model cannot go read your flight log and make memory-off look like memory-on, and only the memory block changes between runs. Answers are checked against the file. If Big Pickle or a flash model gets the control wrong, that is a finding, and you record it; you do not swap models until the numbers look good.

The slide's wording in full
  • Recall. The answer is in a prior session (the model tag in Sortie 3). Memory on must be right; memory off must fail or say it does not know. / Paraphrase. The same fact in other words. This separates bag-of-words from embeddings. / Control. A question memory has no business changing (a fact stated in the prompt, or plain arithmetic). The answer must be identical on and off. / Absent. A fact never stored. Memory on must say 'not in memory'; a confident answer is a fabrication.
  • a fresh session for every run (opencode run starts one) / the same model id both times; record it / every tool denied, so the model cannot read the repository and contaminate the memory-off run / the memory block pasted or omitted, nothing else changed / answers saved verbatim, then checked against the source file, not against the model's confidence
  • A small free model will get some of these wrong. That is data for the flight log, not a reason to change models mid-sortie.
slide 13

Common mistake: a stale fact recalled with confidence

The common mistake. Chapter 16 calls memory a vibing surface: a stale fact, recalled as truth. The worked case is ordinary. A test command from week two is still in the store after you changed it in week four, retrieval finds it on an exact term, the agent runs the wrong command, and reports a pass. Nothing in the answer shows the age of the fact. The fixes: a supersedes field so the correction replaces the original, dates in the injected block, and the authority order from the previous Evolution, where the file beats the memory of the file. The failure mode is number four, skipped cheap verification. When an attacker plants the stale fact on purpose, OWASP's December 2025 list for agentic applications calls it ASI06, memory and context poisoning.

The slide's wording in full
  • Supersedes. A new record names the one it replaces; retrieval drops superseded ids. / Dates in the block. The model and the reader both see the age of what was recalled. / Authority order. The file in the repository beats the memory of the file. In E6 terms a memory is derived (L3); L2 > L1 > L3. / A falsifier on the card: retrieval changes an answer that should not change.
  • App. C #4, skipped cheap verification: the agent trusted a recalled command instead of reading the current file. OWASP's agentic top 10 (Dec 2025) names the adversarial version ASI06, memory and context poisoning.

ADR-2: the memory decision, with alternatives

ADR-2, the memory decision. Five options that a student in this room could defend. No memory is an honest option and fails the sortie claim by design, which is worth saying in the ADR. Bag-of-words and local embeddings are the two lab paths. A hosted memory service works and moves your data and its retention policy to a vendor. The scorecard columns are the ones the Chase checks: install, paraphrase, provenance and deletion, cost and risk.

The slide's wording in full
  • Five real options and the scorecard the Chase checks; ADR-2 is due with Sortie 7
  • You re-explain every session; fails the Sortie 7 claim by design
  • ADR-2 names the kinds of memory kept, the store, the retriever path, the retention rule per kind, and at least three rejected options with their consequences.
slide 16

Teardown: RAG (Lewis et al., 2020)

RAG, read for mechanism. Two memories: the weights of a BART generator, and an index of twenty-one million hundred-word Wikipedia chunks that a trained retriever searches by inner product. The design choice is that knowledge lives outside the weights, and the paper's best experiment shows why: swap a 2016 index for a stale one and accuracy on current leaders falls from seventy percent to four. That is a retention result from 2020. The cost is a retriever and an index to maintain. The failure mode is fabrication, because the generator is free to go beyond its passages; provenance only exists if the answer cites what it used.

The slide's wording in full
  • A BART-large generator (406M parameters) conditioned on passages that a DPR retriever finds in a dense index of the December 2018 Wikipedia dump: 21M chunks of 100 words, searched by maximum inner product (FAISS). / RAG-Sequence uses the same passages for the whole answer; RAG-Token can draw on a different passage for each token. NeurIPS 2020.
  • Choice. Knowledge lives outside the weights, so it can be replaced. The authors swapped indexes: with the 2016 index, 70% of 2016 world-leader questions right; with the 2016 index on 2018 leaders, 4%. / Cost. A retriever to train and an index to keep fresh. / Failure mode. The generator can still answer beyond its passages (App. C #3, fabrication). Retrieval gives provenance only if the answer cites what it used.
  • For your system: the index swap is your retention argument. A memory you can replace is a memory you can correct; weights you cannot.
slide 17

Teardown: Generative Agents (Park et al., 2023)

Generative Agents. The mechanism is the memory stream and a retrieval score that adds three things with equal weight: how recent, how important, how relevant. Importance is the model rating each memory from one to ten, which is a model call per observation, and that is the cost. The design choice is reflection: when enough important things have happened, the agent writes higher-level memories that cite the observations behind them. The paper reports its own failures honestly, and they are the ones you will see: a fact that was in memory and not retrieved, and a memory embellished with world knowledge, the neighbor named Adam Smith who suddenly wrote The Wealth of Nations. Fabrication, number three. The strip connects to E9: reflections without pointers become summaries that nobody can check.

The slide's wording in full
  • A list of memory objects, each with a description, a creation time, and a last-access time. Retrieval score = recency + importance + relevance, all weights 1. Recency decays by 0.995 per game hour since last access; importance is the model's 1–10 rating.
  • When the importance of recent events sums past 150, the agent asks itself questions and stores the answers as higher-level memories that cite their sources. Klaus picks a research partner by reflection, not by who he met most.
  • Model calls to rate every observation and to reflect. The paper's own evaluation: agents failed to retrieve (Rajiv had 'not followed the election') and embellished (Yuriko's neighbor Adam Smith 'authored Wealth of Nations'). App. C #3.
  • Reflection is memory the model writes about itself. Store it with pointers to its evidence, or it becomes summary laundering inside one agent.
slide 18

Teardown: MemGPT to Letta (2023–2026)

MemGPT to Letta in four steps. The 2023 paper splits the prompt into a read-only system part, a small working block the model edits by function call, and a message queue, with two stores outside. The pager warns at about seventy percent and flushes half the queue into a recursive summary at a hundred. In September 2024 the project became Letta, and the authors asked that MemGPT be used for the pattern and Letta for the framework. The interesting step is this February: Letta Code moved memory into files in a git repository, each change a commit. The failure mode is that the model owns its own memory: a wrong fact in the working block is read every turn, and a correction it never saves is gone.

The slide's wording in full
  • Main context: system instructions (read-only), working context (a fixed block the model edits only by function call), and a FIFO message queue. External: recall storage (all messages) and archival storage.
  • A memory-pressure warning at about 70% of the window; at 100%, about half the queue is evicted into a recursive summary. The model moves facts with function calls; interrupts return control.
  • 'MemGPT' becomes the name of the design pattern; Letta is the company and the framework (package letta). Memory blocks with labels such as 'human' and 'persona'.
  • Letta Code keeps agent memory as files in a git-backed filesystem. Each change is a commit; subagents merge memory through git; background skills reflect and defragment.
  • Three years from custom memory functions to files and commits. Failure mode: the model edits its own working context, so a wrong fact written once is read on every turn, and a correction the model does not save is lost (App. C #5).
slide 19

Teardown: Reflexion (Shinn et al., 2023)

Reflexion, in the authors' sentence. Three roles and a tiny episodic memory of one to three lessons in words. The headline is ninety-one percent on HumanEval against eighty for GPT-4 at the time. The mechanism to read is the evaluator: for code, the tests are written by the model. On MBPP one in six of those test runs passed wrong code, and Reflexion did worse there. So the memory is a memory of whatever the evaluator called failure.

Reference design: the insights corpus

The reference design. Its memory is a file of five hundred and fifty-eight governed course-corrections, added through a gz verb, and it feeds the incident casebook you have been reading all term. It is both episodic and procedural: the event and the rule. The design decision, stated in the topic guide, is files and a ledger on purpose, with retrieval left to the book, meaning to you. slide 24

Reference design: memory in the layers of truth

Where memory sits in the layers of truth from the previous Evolution. Canon is what you authored. The ledger is what happened. Derived is everything computed from the other two, and a memory store is derived: it is built from your logs and files. So it can never block a gate and never outvote the file it came from; when they disagree, the file wins and the memory is superseded. The ledger beside the store is what makes the store auditable. That is the default for Sortie 7. If you want memory to be canon for some fact, ADR-2 has to argue it.

State and eviction

  • Working state is a typed object; eviction is a policy with a trigger and a ledger event
  • Working state
  • By pressure (MemGPT)
  • By rule (retention)
  • By relevance (Generative Agents)
  • A typed object the loop owns. The model proposes; the loop validates and writes. Prose is not state.
  • Warning at about 70% of the window; at 100%, half the messages become a recursive summary.
  • retain_until on every record; evict removes past-date records and logs each id. Deterministic and testable.
  • Nothing is deleted. Low-scoring memories stop surfacing. You cannot prove anything is gone.
  • Sortie 7 flies the rule path: each evicted id logged, gone, and no longer recalled.

Retention is governance

  • Four questions every retention rule answers; ADR-2 answers them for each kind of memory you keep
  • Question · Weak answer · Answerable answer
  • Who may write a memory? · 'The agent saves what seems useful' · Named writers: user, rule, or agent with a ledger event; written_by on the record.
  • How long is it kept? · 'Until the store is full' · retain_until per kind: episodic to course end, semantic until superseded, window never persisted.
  • Who can delete it, and how is deletion proved? · 'Delete the file' · forget <id> --reason writes a ledger event; a recall test shows the id gone.
  • Where did it come from? · 'The model remembered' · Source path and date on the record; the answer cites the id.
  • The dates are the course's suggestion. Your ADR-2 sets your own clocks and justifies each one.
  • Deleting the source does not delete the memory. Claude's help center: entries from a deleted chat remain until deleted individually.

Teardown: RAG (Lewis et al., 2020)

  • Parametric memory in the weights; non-parametric memory in an index you can replace
  • Mechanism
  • Choice, cost, failure mode
  • BART-large (406M parameters) conditioned on passages a DPR retriever finds in a dense FAISS index of the December 2018 Wikipedia dump, 21M chunks of 100 words.
    RAG-Sequence: same passages throughout. RAG-Token: a different passage per token. NeurIPS 2020.
  • Choice. Knowledge outside the weights can be replaced. Index swap: 70% on 2016 leaders; 4% on 2018 leaders.
    Cost. A retriever to train and an index to keep fresh.
    Failure mode. The generator can answer beyond its passages (App. C #3).
  • The index swap is your retention argument. A memory you can replace, you can correct.

Teardown: Generative Agents (Park et al., 2023)

  • 25 agents in a sandbox town; a memory stream, retrieval by three scores, and reflection
  • Mechanism: the stream
  • Design choice: reflection
  • Cost and failure mode
  • Memory objects with description, creation time, last-access time. Score = recency + importance + relevance, weights 1. Recency decays 0.995 per game hour; importance is the model's 1–10 rating.
  • When recent importance sums past 150, the agent asks itself questions and stores the answers, citing sources.
  • Model calls to rate and reflect. The paper's own evaluation found failed retrieval (Rajiv) and embellishment (Adam Smith 'authored Wealth of Nations'). App. C #3.
  • UIST '23 · full architecture vs. none: d = 8.16
  • Reflection is memory the model writes about itself. Store it with pointers to its evidence.
