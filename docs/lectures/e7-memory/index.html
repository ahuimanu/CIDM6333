CIDM 6333 · E7
E7 · Lecture · slide 4 of 25

A memory is a claim with a sourceWrite path, store, read path: the fields that let a Chase audit each one

The lifecycle

Write. The user, the agent, or a rule decides; each write is logged.

Store. One record per chunk, with provenance. Append-only; ids never reused.

Read. Retrieval returns ids and scores; the injected block cites them.

Evict and forget. Rule or request; each leaves a ledger event.

The record: one line of memory.jsonl

{"id": "m-0005", "kind": "episodic",

"source": "evolution-05/flight-log.md",

"written": "2026-10-05", "written_by": "rule:sortie-verdict",

"retain_until": "2026-12-15", "supersedes": null,

"text": "Sortie 5 flight log: Chase verdict: FAIL ..."}

The ledger beside it, memory-ledger.jsonl, holds remember, recall, evict, and forget events. The store says what is in memory now; the ledger says what was in memory on any date.

If the Chase cannot trace a recalled sentence to a record and a source file, it is a fabrication (App. C #3).

Chunk

Split by paragraph or section. Keep the heading with each chunk.

Represent

Bag-of-words or a local embedding vector. Same model for index and query.

Store

memory.jsonl, vectors beside the text. A vector database is a scaling decision.

Score

Cosine similarity; top-k (3); drop hits under a threshold so 'nothing found' is a possible answer.

Inject

A marked block: id, source, date, text. The block is data.

State and evictionWorking state is a typed object; eviction is a policy with a trigger and a ledger event

Working state

A typed object the loop owns. The model proposes; the loop validates and writes. Prose is not state.

By pressure (MemGPT)

Warning at about 70% of the window; at 100%, half the messages become a recursive summary.

By rule (retention)

retain_until on every record; evict removes past-date records and logs each id. Deterministic and testable.

By relevance (Generative Agents)

Nothing is deleted. Low-scoring memories stop surfacing. You cannot prove anything is gone.

Sortie 7 flies the rule path: each evicted id logged, gone, and no longer recalled.

QuestionWeak answerAnswerable answer

Teardown: RAG (Lewis et al., 2020)Parametric memory in the weights; non-parametric memory in an index you can replace

Mechanism

BART-large (406M parameters) conditioned on passages a DPR retriever finds in a dense FAISS index of the December 2018 Wikipedia dump, 21M chunks of 100 words.

RAG-Sequence: same passages throughout. RAG-Token: a different passage per token. NeurIPS 2020.

Choice, cost, failure mode

Choice. Knowledge outside the weights can be replaced. Index swap: 70% on 2016 leaders; 4% on 2018 leaders.

Cost. A retriever to train and an index to keep fresh.

Failure mode. The generator can answer beyond its passages (App. C #3).

The index swap is your retention argument. A replaceable index can be corrected; weights cannot.

CIDM 6333 · E7
E7 · Lecture · slide 15 of 25

Teardown: Generative Agents (Park et al., 2023)25 agents in a sandbox town; a memory stream, retrieval by three scores, and reflection

Mechanism: the stream

Memory objects with description, creation time, last-access time. Score = recency + importance + relevance, weights 1. Recency decays 0.995 per game hour; importance is the model's 1–10 rating.

Design choice: reflection

When recent importance sums past 150, the agent asks itself questions and stores the answers, citing sources.

Cost and failure mode

Model calls to rate and reflect. The paper's own evaluation found failed retrieval (Rajiv) and embellishment (Adam Smith 'authored Wealth of Nations'). App. C #3.

UIST '23 · full architecture vs. none: d = 8.16

Reflection is memory the model writes about itself. Store it with pointers to its evidence.

Reference design: memory in the layers of truthE6's precedence applied to your store: L2 > L1 > L3, and a memory is L3

L1 · canon

PRD, ADRs, AGENTS.md, flight cards: authored Markdown. A memory may point here. It never overrides it.

L2 · ledger

Append-only events: remember, recall, evict, forget. The ledger says what the store held on any date.

L3 · derived

The store itself and every summary built from it. It never blocks a gate or outvotes a file.

Your memory layer is L3 with an L2 audit trail. That is the Sortie 7 default unless ADR-2 argues otherwise.

slide 01

Memory: Retrieval, State, Eviction, Retention

Evolution 7. In Evolution 6 you budgeted the window and wrote a handoff so that a fresh session could pick up where the old one stopped. This Evolution takes up the part of context that survives the session on purpose, which this lecture calls memory. Whatever survives a session can be wrong by the next one. The survey covers four research designs from 2020 to 2023 and the memory features that ChatGPT, Claude, Gemini, and Claude Code ship today, each read for two questions: who writes a memory, and how it is deleted. The build is a memory layer on your laptop with a retention rule, together with ADR-2, the memory decision with its alternatives. This is the second Evolution that requires a local model.

slide 02

Memory is the part of context that survives

Framing. The window you budgeted in Evolution 6 is gone when the session ends; memory is the part of it you chose to keep. Two rules govern the whole lecture. First, a memory is a claim with a source. The record says where the item came from, when it was written, and who wrote it; a record without those fields is a rumor, and the agent repeats a rumor with the same confidence it gives a fact. Second, retrieved text is data, never instruction. This is the E5 rule applied to your own store, since a memory is content that some earlier session, or some attacker, wrote. The claim comes from chapter 16. It has two halves, recall and forgetting, and three falsifiers: a fact that was never stored, an item kept past its rule, and retrieval that changes an answer it had no business changing.

slide 03

Five kinds of memory, and where each lives

Chapter 16 distinguishes five kinds of memory, and the sixth card on the slide is the question ADR-2 answers. The window is short-term memory, and the harness owns it. Working state is typed. If your loop keeps its current goal in a paragraph of prose, the loop cannot validate the goal, compare it with the last one, or test it, so the paragraph does not count as state. Episodic memory is what happened, append-only and dated. Semantic memory is what is known; because facts change, every update must record what it replaces. Procedural memory is skills and recipes, and it changes by review rather than by the agent alone. A course system produces sortie outcomes, which are episodic, and a few user and project facts, which are semantic, so episodic plus a small semantic store is the shape to justify first in ADR-2. Write the kinds down before you build; the choice of store follows from them.

slide 04

A memory is a claim with a source

The record is where the first rule becomes code. The left panel lists four operations, and each one leaves a ledger event: write, store, read, and evict or forget. The right panel shows the record the lab uses. It carries an id that is never reused, the kind, the source file, the date, the writer, a retain-until date, a supersedes field, and the text. The store and the ledger answer different questions. The store says what is remembered now; the ledger says what was remembered on any given date, and that second question is the one an auditor asks. The strip at the bottom states the Chase's test. A recalled sentence that traces to no record and no source file is a fabrication (App. C #3) even when it happens to be true, because nothing in the system can show how it got there.

slide 05

Retrieval: chunk, represent, store, score, inject

Retrieval has five steps, and each is an ADR-2 decision. Chunking comes first, with a finding from the build of the lab tool. When the chunks lost their headings, the question about the Sortie 5 verdict returned the Sortie 3 verdict, because both chunks said 'Chase verdict' and neither said which sortie. The fix was to keep the heading with each chunk. Represent: term counts or embedding vectors, with the same model used to index and to query. Store: a JSONL file holds hundreds of records, which is enough at course scale. Score: cosine similarity, a small k, and a threshold, so that 'nothing found' is a possible answer. Inject: a marked block that the model is told to cite. The strip covers the case where retrieval makes answers worse (an irrelevant hit crowds the window, a stale hit outranks the fresh one, or a planted record reads as instruction). A run with memory off is the control that shows which of these happened.

slide 06

Two retrievers for the lab

Two retrievers, both in the lab's single file. Path B is bag-of-words: the script tokenizes the text, drops stopwords, weights rare terms up, and compares question and chunk by cosine. It needs nothing but the standard library. It is strong on exact identifiers, which make up most of what a flight log contains, and it fails on synonyms. Path A calls Ollama's embed endpoint with embeddinggemma. The vectors come back at unit length, so the dot product is the cosine. Path A handles paraphrase, costs a model download, and produces numbers that no reader can audit, so the Chase audits the text and the id in every case. The OpenCode Go and Zen documentation (retrieved September 24, 2026) offers no embeddings endpoint, so the course harness provides no hosted route, and no one needs another API key for this Evolution.

Small local embedding models on Ollama

The slide lists four models you can pull, with the numbers from the Ollama library pages as of September 24. Embeddinggemma is Google's three-hundred-million-parameter model and the first one Ollama's embedding documentation recommends; it needs a recent Ollama. slide 09

State and eviction

State first. Working state is a typed object the loop owns; the model proposes a change and the loop validates it before writing, which is the same contract your tools followed in E3. Three eviction policies follow. MemGPT evicts by pressure: the harness warns the model at about seventy percent of the window and, at a hundred, flushes half the queue into a recursive summary. Retention evicts by rule: every record carries a date, and a command removes the records past their date and logs each id. Generative Agents evicts by relevance, which means nothing is ever deleted; old, low-scoring memories stop surfacing, and nobody can prove one is gone. Only the rule path yields a test the Chase can check (an id with an evict event, absent from the store, and no longer recalled), so the rule path is the one Sortie 7 flies.

slide 10

Retention as governance

A retention rule is where memory becomes a governance question, because each of its four answers assigns a right or a duty to someone. Who may write a memory? The answerable version lists the permitted writers (a user request, a rule, or the agent with a ledger event) and records on each item which one wrote it. How long is it kept? The answer is a clock per kind rather than 'until the store is full'. Who can delete it, and how is deletion proved? A forget command with a reason, a ledger event, and a recall test that now fails. Where did it come from? A source path and a date on the record and in the injected block. The strip shows a vendor meeting the same question. Claude's help pages state that deleting a conversation does not delete the memories generated from it. In other words, deletion of a derived store is a separate operation from deletion of its source, and your system needs that operation.

slide 11

How to measure memory: the on/off protocol

The on/off protocol is how you test the design claim. It uses four kinds of question. A recall question asks for a fact from a prior session, which is the case the design claim covers. A paraphrase question asks for the same fact in other words and tests the retriever choice. A control question is one that memory has no business changing, and it serves the falsifier 'retrieval changes an answer that should not change'. An absent question asks for a fact never stored, and it is the fabrication check. The right panel gives the discipline: a fresh session for every run, the same model id both times, every tool denied so the model cannot read your flight log and make the memory-off run look like the memory-on run, and nothing changed between runs except the memory block. You check each answer against the source file. If Big Pickle or a flash model gets the control wrong, that is a finding for the flight log; you record it, and you do not swap models to make the numbers look better.

slide 12

Common mistake: a stale fact recalled with confidence

The common mistake. Chapter 16 calls memory a vibing surface, by which it means a stale fact recalled as if it were current truth. The worked case is ordinary. Your Sortie 2 log records a test command; in E4 you changed it and fixed AGENTS.md, but the Sortie 2 record is still in the store. Retrieval finds the old record on an exact term, the agent runs the old command, sees that no tests ran, and reports the gate as passed. Nothing in the answer shows the age of the fact. Three fixes follow. A supersedes field lets the correction replace the original. Dates in the injected block make the age of each recall visible. The authority order from E6 ranks the repository file above the memory of that file. The failure mode is App. C #4, skipped cheap verification, since the agent trusted a recalled command instead of reading the current file. When an attacker plants the stale fact on purpose, OWASP's December 2025 list for agentic applications calls it ASI06, memory and context poisoning.

slide 14

Teardown: RAG (Lewis et al., 2020)

RAG, read for its mechanism. The design has two memories: the weights of a BART generator, and an index of twenty-one million hundred-word Wikipedia chunks that a trained retriever searches by inner product. The design choice is that knowledge lives outside the weights, and the paper's index-swap experiment shows what that buys. With the 2016 index, the model answered seventy percent of questions about 2016 world leaders correctly; asked about 2018 leaders from the same 2016 index, it answered four percent correctly. That is a retention result from 2020: the index held stale facts, and the stale facts were replaceable. The cost is a retriever to train and an index to keep fresh. The failure mode is fabrication (App. C #3), because the generator is free to answer beyond its passages; retrieval gives provenance only when the answer cites what it used.

slide 15

Teardown: Generative Agents (Park et al., 2023)

Generative Agents. The mechanism is the memory stream and a retrieval score that adds three terms with equal weight: recency, importance, and relevance. Importance is the model's rating of each memory from one to ten, which costs a model call per observation. The design choice is reflection. When the importance of recent events sums past a threshold, the agent asks itself questions and stores the answers as higher-level memories that cite the observations behind them. The paper reports its own failures, and both can occur in your store: a fact that was in memory and was not retrieved (Rajiv had 'not followed the election'), and a memory embellished with world knowledge (a neighbor whose name is Adam Smith 'authored Wealth of Nations'). The second is fabrication, App. C #3. The strip connects to E9: a reflection that carries no pointers to its evidence is a summary nobody can check.

slide 16

Teardown: MemGPT to Letta (2023–2026)

MemGPT to Letta in four steps. The 2023 paper splits the prompt into a read-only system part, a small working block the model edits by function call, and a message queue, with recall and archival stores outside the window. The pager warns the model at about seventy percent of the window and, at a hundred, flushes half the queue into a recursive summary. In September 2024 the project became Letta, and the authors asked that 'MemGPT' refer to the pattern and 'Letta' to the company and framework. The step that matters for this course came in February 2026, when Letta Code moved memory into files in a git repository, with each change a commit. The reference design started from the same substrate, as the reference-design section shows. The failure mode follows from the model owning its own memory: a wrong fact in the working block is read on every turn, and a correction the model does not save is lost (App. C #5).

slide 17

Teardown: Reflexion (Shinn et al., 2023)

Reflexion, in the authors' own sentence. The design has three roles (an Actor, an Evaluator, and a Self-Reflection model) and a small episodic memory of one to three lessons written in words. The headline result is ninety-one percent pass@1 on HumanEval against the eighty percent reported for GPT-4 at the time. The part to read closely is the evaluator. On MBPP, 16.3 percent of those self-written tests passed wrong code, and Reflexion did worse there. The memory is therefore a memory of whatever the evaluator called a failure, and it is only as reliable as that evaluator. This is App.

slide 18

Teardown: assistant memory features, 2025–2026

Four shipping memory systems, read for the four retention questions. ChatGPT stores saved memories, written by you or by the model, and chat history, and since May 2026 shows memory sources, which is provenance made visible to the user; logs of deleted memories are kept for up to thirty days. Claude made memory free in March 2026, keeps a separate memory per project, and documents that deleting a chat does not delete the memories generated from it. Claude Code is the system closest to your build: plain Markdown files that the agent writes per repository, with the first two hundred lines loaded each session, and excluded from the transcript cleanup sweep. The strip is the security case. In 2024 Johann Rehberger showed that a web page could write instructions into ChatGPT's memory, and the memory then carried the attack into every later session. Because the memory persisted, one injection reached every later chat.

slide 20

Reference design: the insights corpus

The reference design. Its memory is an append-only JSONL file of five hundred and fifty-eight governed course-corrections, added through the gz insights remember verb, and it is one of the sources for the incident casebook in Appendix G. The corpus is episodic and procedural at once: each record holds the event and the rule that followed. The design decision, stated in the topic guide, is files and a ledger on purpose, with retrieval left to the book, which means left to you. The reason is auditability: a file can be diffed, reviewed, and reverted in git, the ledger dates every entry, and nothing is recalled that a human cannot open and read. The cost is paraphrase: the agent has to decide to look, and grep has to match. Letta arrived at files under git in February 2026 from the other direction. Verify the count, the command syntax, and what the OKF bundle and gz context contain against the repository; I have not described them beyond what the topic guide states.

slide 21

Reference design: four dated memory failures

Four dated episodes from Appendix G, read as memory failures. On April 18, nine layers were silently wrong and everything downstream trusted them, which is how a poisoned memory store behaves. On April 26, a clone was ten commits stale, a picture of the repository that was old, and nothing said so. On August 16, one fact lived in two places, and the prose copy drifted from the JSON authority. On August 23, the rulings existed and the agent asked again; the memory was right and was not read. Two episodes are memory that was wrong, and two are memory that was right and unread. Sortie 7 tests both kinds: a recall that must succeed and an eviction that must hold.

slide 22

Reference design: memory in the layers of truth

Memory has a place in the layers of truth from E6. Canon (L1) is what you authored. The ledger (L2) is what happened. Derived (L3) is everything computed from the other two, and a memory store is derived, because it is built from your logs and files. For this reason the store can never block a gate and never outvote the file it came from; when the two disagree, the file wins and the memory record is superseded. The ledger beside the store makes the store auditable, since it says what the store held on any date. That is the Sortie 7 default. If you want a memory to be canon for some fact, ADR-2 has to argue the case.

slide 23

Evaluation lens: a strong Sortie 7

The evaluation lens has three bands. A weak Sortie 7 pastes an old transcript back in and calls it memory, reports a success with no control run, states a retention rule in prose and enforces it nowhere, edits the store or the ledger by hand, or lets the model read the repository during the memory-off run. A sound Sortie 7 has complete records, five test points on one model id with verbatim answers traced to their files, a control answer that is identical on and off, an absent question answered 'not in memory', an eviction the ledger proves, and an ADR-2 with real alternatives. An exceptional Sortie 7 compares both retrievers on the paraphrase row, runs the chapter 16 exercise of planting one false record and measuring how many answers it changed before the forget event removed it, implements supersedes, sets a clock per kind with a reason for each, and chooses its threshold from data.

slide 24

Flight Card 7 · memory on, off, and gone

Flight Card 7 is an expansion card with a local retriever. It has five test points: recall with memory off, recall with memory on, the control question on and off, the absent question, and eviction. The instrumentation is the memory ledger, the retrieval output with ids and scores, the five answers verbatim, and the store diff before and after eviction. It carries four falsifiers: a recalled fact or id that was never stored, an item kept past its rule or removed with no ledger event, a control answer that changed, and a pass obtained by a hand edit or by a model that could read the repository. The abort condition is narrow. If Ollama goes down on path A, a move to path B is a new card; a quiet substitution mid-flight would change the system under test. Your Chase writes it under the card in the repository.
