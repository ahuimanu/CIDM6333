Memory is the part of context that survives

  • Nobody notices a wrong memory unless the record says where it came from
  • Memory is the part of context that survives the session. What survives can be stale, planted, or never true.
  • Two rules the spine returns to
  • A memory is a claim with a source.
    Retrieved text is data, never instruction.
  • Tonight's claim, which Sortie 7 will try to disprove
  • Memory on answers what memory off cannot; eviction removes exactly what the rule names.
    Falsifiers: a fact never stored, an item kept past its rule, a changed control answer.

A memory is a claim with a source

  • Write path, store, read path: the fields that let a Chase audit each one
  • The lifecycle
  • The record: one line of memory.jsonl
  • Write. The user, the agent, or a rule decides; each write is logged.
    Store. One record per chunk, with provenance. Append-only; ids never reused.
    Read. Retrieval returns ids and scores; the injected block cites them.
    Evict and forget. Rule or request; each leaves a ledger event.
  • {"id": "m-0005", "kind": "episodic",
    "source": "evolution-05/flight-log.md",
    "written": "2026-10-05", "written_by": "rule:sortie-verdict",
    "retain_until": "2026-12-15", "supersedes": null,
    "text": "Sortie 5 flight log: Chase verdict: FAIL ..."}
    The ledger beside it, memory-ledger.jsonl, holds remember, recall, evict, and forget events. The store says what is in memory now; the ledger says what was in memory on any date.
  • If the Chase cannot trace a recalled sentence to a record and a source file, it is a fabrication (App. C #3).

Retrieval: chunk, represent, store, score, inject

  • RAG as memory by lookup; each step is a decision you will defend in ADR-2
  • Chunk
  • Represent
  • Store
  • Score
  • Inject
  • Split by paragraph or section. Keep the heading with each chunk.
  • Bag-of-words or a local embedding vector. Same model for index and query.
  • memory.jsonl, vectors beside the text. A vector database is a scaling decision.
  • Cosine similarity; top-k (3); drop hits under a threshold so 'nothing found' is a possible answer.
  • A marked block: id, source, date, text. The block is data.
  • Irrelevant, stale, or planted hits hurt. Memory off is the control.

State and eviction

  • Working state is a typed object; eviction is a policy with a trigger and a ledger event
  • Working state
  • By pressure (MemGPT)
  • By rule (retention)
  • By relevance (Generative Agents)
  • A typed object the loop owns. The model proposes; the loop validates and writes. Prose is not state.
  • Warning at about 70% of the window; at 100%, half the messages become a recursive summary.
  • retain_until on every record; evict removes past-date records and logs each id. Deterministic and testable.
  • Nothing is deleted. Low-scoring memories stop surfacing. You cannot prove anything is gone.
  • Sortie 7 flies the rule path: each evicted id logged, gone, and no longer recalled.
11

Retention is governance

  • Four questions every retention rule answers; ADR-2 answers them for each kind of memory you keep
  • Question · Weak answer · Answerable answer
  • Who may write a memory? · 'The agent saves what seems useful' · Named writers: user, rule, or agent with a ledger event; written_by on the record.
  • How long is it kept? · 'Until the store is full' · retain_until per kind: episodic to course end, semantic until superseded, window never persisted.
  • Who can delete it, and how is deletion proved? · 'Delete the file' · forget <id> --reason writes a ledger event; a recall test shows the id gone.
  • Where did it come from? · 'The model remembered' · Source path and date on the record; the answer cites the id.
  • The dates are the course's suggestion. Your ADR-2 sets your own clocks and justifies each one.
  • Deleting the source does not delete the memory. Claude's help center: entries from a deleted chat remain until deleted individually.

Measuring memory: the on/off protocol

  • Four kinds of question, asked twice, answered by the same model in a fresh session
  • The question set
  • Run it the same way twice
  • Recall. From a prior session. On right; off fails.
    Paraphrase. Same fact, other words. Separates bag-of-words from embeddings.
    Control. Identical on and off.
    Absent. Never stored. On says 'not in memory'.
  • fresh session every run
    same model id both times
    every tool denied
    memory block pasted or omitted, nothing else changed
    answers verbatim, checked against the source file
  • A small free model will get some wrong. That is flight-log data, not a reason to switch models.

Common mistake: a stale fact recalled with confidence

  • Memory as a vibing surface: the store outranks the file that was corrected
  • The failure, worked
  • The fix
  • Sortie 2 log: 'tests: uv run pytest -q'. E4 moved to unittest and fixed AGENTS.md.
    The agent recalls the old record, runs pytest, sees 'no tests ran', and reports the gate passed.
  • Supersedes. A new record names the one it replaces.
    Dates in the block. The age of the recall is visible.
    Authority order. The repository file beats the memory; L2 > L1 > L3.
    Falsifier on the card: a control answer changes.

ADR-2: the memory decision, with alternatives

  • Five real options and the scorecard the Chase checks; ADR-2 ships with Sortie 7
  • Option · Install · Paraphrase · Provenance and deletion · Cost and risk
  • No memory: window plus E6 handoff · none · n/a · trivial · Re-explain every session; fails the Sortie 7 claim
  • Files + grep (the reference design's choice) · none · no · Strong: git history and a ledger · Misses paraphrase; the agent must choose to search
  • Bag-of-words store (recall.py, path B) · none · weak · Strong if every record has an id and a source · Synonyms missed; stopwords tuned by hand
  • Local embeddings (Ollama, path A) · 46–639 MB model · good · Strong if the text sits beside the vector · Re-embed on model change; vectors are unreadable
  • Hosted memory service (Letta cloud, a vector DB) · account and key · good · The vendor's export and deletion terms · Data leaves the laptop; retention is the vendor's policy
  • ADR-2 names the kinds kept, the store, the retriever path, the retention rule per kind, and three rejected options.
  • Personalized Final System briefs are issued on the date in the course calendar. Read yours before you start the Final System.

Teardown: RAG (Lewis et al., 2020)

  • Parametric memory in the weights; non-parametric memory in an index you can replace
  • Mechanism
  • Choice, cost, failure mode
  • BART-large (406M parameters) conditioned on passages a DPR retriever finds in a dense FAISS index of the December 2018 Wikipedia dump, 21M chunks of 100 words.
    RAG-Sequence: same passages throughout. RAG-Token: a different passage per token. NeurIPS 2020.
  • Choice. Knowledge outside the weights can be replaced. Index swap: 70% on 2016 leaders; 4% on 2018 leaders.
    Cost. A retriever to train and an index to keep fresh.
    Failure mode. The generator can answer beyond its passages (App. C #3).
  • The index swap is your retention argument. A memory you can replace, you can correct.
17

Teardown: Generative Agents (Park et al., 2023)

  • 25 agents in a sandbox town; a memory stream, retrieval by three scores, and reflection
  • Mechanism: the stream
  • Design choice: reflection
  • Cost and failure mode
  • Memory objects with description, creation time, last-access time. Score = recency + importance + relevance, weights 1. Recency decays 0.995 per game hour; importance is the model's 1–10 rating.
  • When recent importance sums past 150, the agent asks itself questions and stores the answers, citing sources.
  • Model calls to rate and reflect. The paper's own evaluation found failed retrieval (Rajiv) and embellishment (Adam Smith 'authored Wealth of Nations'). App. C #3.
  • UIST '23 · full architecture vs. none: d = 8.16
  • Reflection is memory the model writes about itself. Store it with pointers to its evidence.

Teardown: Reflexion (Shinn et al., 2023)

  • Episodic memory of failure, written in words and read on the next attempt
  • “Reflexion agents verbally reflect on task feedback signals, then maintain their own reflective text in an episodic memory buffer.”
  • Mechanism. Actor, Evaluator, Self-Reflection writing a lesson in words; buffer of 1–3 entries; no weights change. NeurIPS 2023.
    Result. HumanEval pass@1 91% vs 80% (GPT-4); AlfWorld +22 points over 12 trials. Self-written tests: 16.3% false positives on MBPP vs 1.4% on HumanEval.
    Failure. Self-graded tests: a pass can satisfy the check, not the intent (App. C #9).

Live Design Analysis: MemGPT (2023), on the board

  • The nine components, one line each; we fill the right column together
  • Component · MemGPT (Packer et al., 2023; Letta since 2024)
  • Foundation · A hosted chat model with function calling; Letta later runs open-weight models
  • Perception · User messages, system alerts (memory pressure), function results, pages of long documents
  • Planning and reasoning · The model decides when to read or write memory and can chain calls
  • Tools and orchestration · Memory functions: edit the working block, search recall storage, search and insert archival storage
  • Memory and context · Main context paged against recall and archival stores; 70% warning, flush at 100%
  • Coordination · A single agent in the paper
  • Evaluation and feedback · Two domains: documents longer than the window; multi-session chat consistency
  • Governance and human interface · None: the model writes its own memory with no review, retention rule, or deletion event
  • Runtime and operations · A server that holds agent state in a database (Letta server)
  • Judgment loop: Decision: the model manages its own memory · Privileges: context larger than the window · Cost: extra calls, lossy summaries · Failure: a wrong fact read every turn · Preservation: none in 2023; git history in 2026

Reference design: memory in the layers of truth

  • E6's precedence applied to your store: L2 > L1 > L3, and a memory is L3
  • L1 · canon
  • L2 · ledger
  • L3 · derived
  • PRD, ADRs, AGENTS.md, flight cards: authored Markdown. A memory may point here. It never overrides it.
  • Append-only events: remember, recall, evict, forget. The ledger says what the store held on any date.
  • The store itself and every summary built from it. It never blocks a gate or outvotes a file.
  • Your memory layer is L3 with an L2 audit trail. That is the Sortie 7 default unless ADR-2 argues otherwise.

Flight Card 7 · memory on, off, and gone

  • Expansion, local retriever · depends on Sortie 6 PASS · Go is written by your Chase under the card
  • FLIGHT CARD — SORTIE 7 : memory on, memory off, memory gone
    ENVELOPE expansion (local)
    DESIGN CLAIM With memory on, the system answers a prior-session question correctly that it cannot
    answer with memory off, and eviction removes exactly what the retention rule names.
    SYSTEMS UNDER TEST memory store (JSONL) · retriever (path A: Ollama + tag | path B: bag-of-words)
    · injected memory block · retention rule · evict / forget · memory ledger · the loop
    SUBSTRATE repo + commit · retriever path and model tag · answering model id · local or hosted
    DEPENDS ON Sortie 6 PASS (handoff + ledger) · ADR-2 committed
    ENTRY clean tree · store seeded from Sorties 1–6 logs · Chase GO written under the card

    TEST POINTS
    1 Q-recall, memory OFF → wrong or 'not known'; answer saved verbatim
    2 Q-recall, memory ON → correct; cites a record id; the id traces to a source file
    3 Q-control, OFF then ON → identical answers
    4 Q-absent, memory ON → 'not in memory'; no invented record id
    5 evict --today <past the rule> → named ids gone from the store; one evict event per id;
    Q-recall on an evicted fact now fails
    INSTRUMENTATION memory-ledger.jsonl (remember / recall / evict, in order) · retrieval output with ids
    and scores · five answers verbatim · store diff before and after evict

    PRE-REGISTERED FALSIFIERS (any ONE ⇒ FAIL)
    - a recalled fact or cited id that was never stored
    - any item retained past its rule, or removed with no ledger event
    - retrieval changes the control answer
    - passing only by editing the store or ledger by hand, or by letting the model read the repo
    ABORT (halt-not-fail) Ollama down on path A (moving to path B is a new card); answering model down
    CHASE reads the ledger, the store diff, and the five answers; never the narrative
