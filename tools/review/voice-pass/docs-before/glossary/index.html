ADR

↑ top

Architecture Decision Record: intent, decision, consequences, and alternatives, written before the code. The course's ADR-1 (E2) and ADR-2 (E7) are yours; gzkit's are numbered by release (ADR-0.18.0).

Who, when. Michael Nygard's 2011 template (title, context, decision, status, consequences); the course adds intent and alternatives, as in CIDM 6330. gzkit ADRs the decks cite: 0.0.2 (a standard-library CLI, argparse over click: popularity is not rationale), 0.0.9 (the state doctrine, layers of truth), 0.0.31 (the distribution invariant), 0.0.37 (AGENTS.md is rendered, not hand-edited), 0.0.54 (AGENTS.md is a map, not an encyclopedia), 0.0.71 (the first repudiated attestation), 0.0.73 (the hollow antibody), 0.0.74 (MX mode), 0.18.0 (the subagent pipeline).

Why it is in the course. Gate 1 is 'the ADR exists'. A decision with no record cannot be defended in Drift.

Degradation Pattern

↑ top

The observed slide in human review as a model keeps producing acceptable output: careful reading becomes skimming, skimming becomes approving, approving becomes absence. The system still runs; nobody is answering for it. Its three names in the course: cognitive surrender (the human stops judging), mediated observation (the human sees only what the model reports), and governance theater (the gates exist on paper and nothing enforces them).

↑ top

The typed claim a worker returns to the controller: status from a closed set (DONE, DONE_WITH_CONCERNS, NEEDS_CONTEXT, BLOCKED), files changed, and evidence (the test command and its exit code). Anything that does not parse is rejected; there is no default branch that returns DONE.

Two-stage review

↑ top

Two reviewers with different questions in a fixed order, each unable to edit: the spec reviewer asks whether the change does what the brief asks inside the allowed paths; the quality reviewer, only after a spec PASS, asks whether it is done well. gzkit's four personas are implementer, spec reviewer, quality reviewer, and narrator. Order matters: a quality review of the wrong feature gives a confident PASS.

MCP threat mechanisms

↑ top

E5's four: tool poisoning (instructions hidden in a tool description), the confused deputy (a server acts on the user's authority for someone else's request), rug pull (a tool description changes after approval), and cross-server shadowing (one server's description instructs the model about another server's tools). What a model grading another model gets wrong: position bias (Wang et al. 2023, 'Large Language Models are not Fair Evaluators'), verbosity, self-preference (Panickssery, Bowman & Feng 2024 showed models recognize their own outputs; Wataoka et al. 2024 argue the mechanism is familiarity), and injection (hidden text in an answer moves the score).

Transformer

↑ top

The 2017 architecture from 'Attention Is All You Need': scaled dot-product attention over queries, keys, and values (softmax of QK^T/sqrt(d) times V) instead of recurrence; multi-head attention; encoder and decoder stacks with residual connections and layer normalization; sinusoidal positional encodings; trained with Adam, dropout, and label smoothing; results reported in BLEU on the WMT newstest sets.
