Skill on Demand

A skill is a procedure with a name. OpenCode finds it on disk. At the start of a session the model sees only its name and a short description. The full text loads only when the model calls the skill tool. This figure follows one skill, flight-card, from its folder to the turn it runs on, and shows three ways it fails to run.

Will it trigger?

Edit the description or the request, then press Check. The page lowercases both, splits them into words, and counts the description words of four or more letters that also appear in the request ("this" and "repository" are skipped). Matches are highlighted in both strings. This is an illustrative word match, not the model's decision. The model reads the description as text; it has no matcher.

Frontmatter check

The name must be 1 to 64 characters of lowercase letters and digits with single hyphens, and it must equal the directory name. A skill that fails any rule is never listed.

A skill keeps a procedure out of the way until it is needed, so the model reads the steps only on the turn it uses them, and follows them better than steps buried in a long instruction file. Under allow the call still happens but no prompt is shown, so the proof moves to the ledger and to the verbatim quote. Under deny the model is told the call was refused and must go on without the body.
